## Add Stophy to your client

Each of these connects to `https://mcp.stophy.dev/mcp` and opens your browser to sign in, so your agent can use every endpoint.

<CodeGroup>

```bash Claude Code
claude mcp add --transport http stophy https://mcp.stophy.dev/mcp
# then run /mcp in Claude Code, choose stophy and pick Authenticate
```

```bash Codex
codex mcp add stophy --url https://mcp.stophy.dev/mcp
codex mcp login stophy
```

```bash Gemini CLI
gemini extensions install https://github.com/stophydotdev/stophy
# then run /mcp auth stophy in Gemini CLI
```

```json Cursor (~/.cursor/mcp.json)
{
  "mcpServers": {
    "stophy": { "url": "https://mcp.stophy.dev/mcp" }
  }
}
```

```json Windsurf (~/.codeium/windsurf/mcp_config.json)
{
  "mcpServers": {
    "stophy": { "serverUrl": "https://mcp.stophy.dev/mcp" }
  }
}
```

```json OpenCode (opencode.json)
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "stophy": {
      "type": "remote",
      "url": "https://mcp.stophy.dev/mcp",
      "enabled": true
    }
  }
}
```

</CodeGroup>

VS Code connects with no key or an API key. See [No key and API key](/mcp-server/keyless).

## Add Stophy to a chat app

- **Claude** on the web, desktop or mobile: open **Customize > Connectors**, click **+ Add**, then **Add custom connector**, and paste `https://mcp.stophy.dev/mcp`. See [Claude Desktop](/quickstarts/claude-desktop).
- **Grok** on grok.com: open [grok.com/connectors](https://grok.com/connectors), click **New Connector**, then **Custom**, paste `https://mcp.stophy.dev/mcp` and sign in.

## Choose how to connect

| | URL | Endpoints |
| --- | --- | --- |
| Browser sign-in | `https://mcp.stophy.dev/mcp` | Every endpoint |
| API key | `https://api.stophy.dev/mcp` with `Authorization: Bearer <key>` | Every endpoint |
| No key | `https://api.stophy.dev/mcp` | Search, scrape, map and parse, within the [free limits](/rate-limits) |

Both are server URLs for your client, not pages to open in a browser. [Browser sign-in](/mcp-server/oauth) explains what happens when you approve the app.

## What your agent sees

| Tool | What it does |
| --- | --- |
| `stophy_search` | Searches the web, news and images |
| `stophy_scrape` | Reads a page as markdown, HTML, links, a screenshot or JSON |
| `stophy_map` | Lists the pages on a site |
| `stophy_crawl` | Starts a crawl of a site in the background and returns its `id` |
| `stophy_extract` | Pulls the fields you name from pages as JSON |
| `stophy_search_endpoints` | Finds the endpoint for a task, with its cost. Free |
| `stophy_describe_endpoint` | Shows an endpoint's inputs, an example and what it returns. Free |
| `stophy_call` | Runs any endpoint by `id` with `input`, and optional `fields` and `maxTextLength` |
| `stophy_signup` | Gets your agent an API key: it returns a link for you to approve, then the key once you call it with the code |

Ask *"What are people saying about Bun on Reddit?"* and your agent calls `stophy_scrape` with a Reddit search page and the `reddit-search` [parser](/guides/parsers):

```json
{
  "url": "https://www.reddit.com/search/?q=bun+runtime",
  "formats": [{ "type": "json", "parser": "reddit-search" }]
}
```

A crawl runs in the background. Your agent reads it with `stophy_call`, `id` `crawlStatus` and the crawl's `id`. Over MCP, endpoint ids are camelCase, like `crawlStatus` or `batchScrape`. A call costs the same as over HTTP. See [Pricing](/billing).

To give each endpoint its own tool, add `toolsets` to the URL with a source name:

```text
https://api.stophy.dev/mcp?toolsets=web
```
