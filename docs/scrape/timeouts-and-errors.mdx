Set `timeout` to limit how long we try to read a page. If the call fails, use its `code` to decide whether to retry or change the request. A failed read costs nothing.

## Make a request

Get an API key in the [Quickstart](/quickstart). This request reads a page that answers after 10 seconds, with a timeout of 3 seconds.

<CodeGroup>
```bash cURL
curl -X POST https://api.stophy.dev/v1/scrape \
  -H "Authorization: Bearer $STOPHY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://httpbin.org/delay/10",
    "timeout": 3000
  }'
```
```typescript TypeScript
import { Stophy, StophyError } from "stophy";

const stophy = new Stophy({ maxRetries: 0 });

try {
  await stophy.scrape({
    url: "https://httpbin.org/delay/10",
    timeout: 3000,
  });
} catch (error) {
  if (error instanceof StophyError) {
    console.log(error.code, error.retryable, error.retryAfterSeconds);
  }
}
```
```python Python
from stophy import Stophy, StophyError

stophy = Stophy(max_retries=0)

try:
    stophy.scrape(
        url="https://httpbin.org/delay/10",
        timeout=3000,
    )
except StophyError as error:
    print(error.code, error.retryable, error.retry_after_seconds)
```
</CodeGroup>

## Read the response

Check the HTTP status and `retryable` before you use the result. Here the read ran out of time, so the call failed with HTTP `504` and a `Retry-After` header of `5`. Nothing was charged. The SDKs retry this error by default. `maxRetries: 0` (`max_retries=0` in Python) shows the first answer.

```json
{
  "success": false,
  "error": "The source took too long to answer. Try again.",
  "code": "sourceTimeout",
  "retryable": true,
  "retryAfterSeconds": 5,
  "requestId": "3da42cac-462f-4e32-a8c5-b5a5841d7ddf"
}
```

Every error has this flat shape. `code` is stable, so branch on it. `error` says what went wrong and what to do. `retryable` says whether sending the same call again can help, and `retryAfterSeconds`, with the `Retry-After` header, says how long to wait. Keep `requestId` for support. See [Errors](/api-reference/errors).

## Options

Raise the timeout for a page that needs longer to load or run actions.

| Field | Type | Default | Effect |
| - | - | - | - |
| `timeout` | `number` | `60000` | How long to keep trying, in milliseconds, from 1,000 to 300,000. |

A page that needs a browser needs at least 5 seconds. A slow page can need 10 to 30 seconds the first time. [Waits](/scrape/waiting-and-rendering) and [actions](/scrape/browser-actions) use up the same time. Set your own client timeout longer than `timeout`, with a few seconds to spare.

## Error codes

Use the error code to pick the next action. Retrying will not fix an invalid request or a missing key.

| `code` | Status | What happened | What to do |
| - | - | - | - |
| `invalidRequest` | 400 | A field is wrong, such as `timeout` below 1,000, an `includeTags` that matches nothing on the page, a file Scrape cannot read, a file larger than 20 MB, or a URL on a private network. The `error` names the field. | Fix the request. Do not retry it as it is. |
| `apiKeyRequired` | 401 | The call needs an API key: an option such as `actions`, `waitFor`, `profile`, `checkPromptInjection`, `redactPII` or `onlyCleanContent`, the formats `audio`, `video` or `json` with a schema or prompt, or a page that only reads with an API key. | Send an API key. See the [Quickstart](/quickstart). |
| `unauthorized` | 401 | The API key is not valid or has expired. | Use a valid API key. |
| `insufficientCredits` | 402 | Your balance is lower than the most the call can cost. Nothing was charged. | Add funds, then send it again. |
| `siteNotRead` | 403 | Stophy does not read pages on this site. | Use a [parser](/scrape/prebuilt-parsers) for it if one exists, or [search](/search/overview) for the topic. |
| `promptInjectionDetected` | 403 | `checkPromptInjection` found instructions aimed at an AI model. See [Safety](/scrape/safety). | Do not feed the page to a model, or send `checkPromptInjection: false`. |
| `notFound` | 404 | The page has no readable text, the domain has no website, or `lockdown` or `minAge` found no stored copy. | Check the URL. |
| `profileBusy` | 409 | Another call is saving to the same browser profile. | Wait for it, or send `saveChanges: false`. |
| `freeLimit`, `rateLimited` | 429 | You are over the free limit or your rate limit. | Wait `retryAfterSeconds`. See [Rate limits](/production/rate-limits). |
| `internalError` | 500, 503 | A failure on our side. | Retry in a second. |
| `sourceChanged` | 502 | The answer came back in a shape Stophy could not read. | Retrying will not help yet. Check back later. |
| `busy` | 503 | Stophy is busy. | Wait `retryAfterSeconds`, 5 to 30 seconds. |
| `sourceUnavailable` | 503 | The page did not finish loading, or could not be reached. | Retry after `retryAfterSeconds`. If it keeps failing, raise `timeout`. |
| `sourceRefused` | 503 | The site is refusing the read right now. | Retry after `retryAfterSeconds`, usually minutes. |
| `sourceTimeout` | 504 | The page did not answer within `timeout`. The `Retry-After` header and `retryAfterSeconds` are 5. | Retry after `retryAfterSeconds`. If it keeps failing, raise `timeout`, or ask for less: fewer formats, fewer actions. |

A page that answers 404 or 410 comes back as a page, with that `metadata.statusCode` and an error such as `The page answered with status 404.` It costs nothing. The same holds for each page of a [crawl](/crawl/async).

## Retry a failed read

Retry only when `retryable` is `true`. Wait `retryAfterSeconds`, or back off 0.5, 1 and 2 seconds. After three tries, stop and log the `requestId`. A retry costs nothing extra, because a failed read is free. [Production troubleshooting](/production/troubleshooting) has a retry loop.

## Many pages

Use a batch if you have a list of URLs and need to tell which pages failed.

Scrape reads one URL. A body with `urls` returns `400 invalidRequest` with the message `urls: Send url. To read many pages in one call, use POST /v1/batch/scrape.` To read a list of URLs, send them to a [batch](/batches/overview). Each page of a batch or a [crawl](/crawl/async) succeeds or fails on its own, so one bad page does not fail the rest. The failed pages are listed with their own `code`, `message` and `retryable`.

## Warnings

Some problems do not fail the call. The page still comes back, with a `warning` that says what happened:

- A [browser action](/scrape/browser-actions) failed, so the page is as it stood before it.
- The text was cut by `maxChars`, and the warning gives the `offset` to read on from.
- `onlyCleanContent` was skipped, or `checkPromptInjection` could not scan the whole page.

## Limits and errors

Check the time and size limits before you retry.

- `timeout` outside 1,000 to 300,000 returns `400 invalidRequest`.
- The most a single call can run is 5 minutes plus a few seconds.
- A page with more than 8 MB of text, or a file larger than 20 MB, returns `400 invalidRequest`.
