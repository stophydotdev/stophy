Use `json` when your code needs fields rather than the whole page. Send a JSON Schema for fixed names and types, or a plain-words prompt when the names can vary.

## Fill a schema

Get an API key in the [Quickstart](/quickstart). Send `json` as an object with a `schema`. This request reads three facts from a documentation page.

<CodeGroup>
```bash cURL
curl -X POST https://api.stophy.dev/v1/scrape \
  -H "Authorization: Bearer $STOPHY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://bun.com/docs/runtime/bunfig",
    "formats": [
      {
        "type": "json",
        "schema": {
          "type": "object",
          "properties": {
            "configFile": { "type": "string" },
            "globalPaths": {
              "type": "array",
              "items": { "type": "string" }
            },
            "hasTelemetryOption": { "type": "boolean" }
          }
        }
      }
    ]
  }'
```
```typescript TypeScript
import { Stophy } from "stophy";

const stophy = new Stophy();

const { data } = await stophy.scrape({
  url: "https://bun.com/docs/runtime/bunfig",
  formats: [
    {
      type: "json",
      schema: {
        type: "object",
        properties: {
          configFile: { type: "string" },
          globalPaths: {
            type: "array",
            items: { type: "string" },
          },
          hasTelemetryOption: { type: "boolean" },
        },
      },
    },
  ],
});
console.log(data.json);
```
```python Python
from stophy import Stophy

stophy = Stophy()

data = stophy.scrape(
    url="https://bun.com/docs/runtime/bunfig",

                        "items": {"type": "string"},
                    },
                    "hasTelemetryOption": {"type": "boolean"},
                },
            },
        },

print(data["json"])
```

## Read the response

Read `data.json` for the values under the keys in your schema.

```json
{
  "success": true,
  "data": {
    "json": {
      "configFile": "bunfig.toml",
      "globalPaths": [
        "$HOME/.bunfig.toml",
        "$XDG_CONFIG_HOME/.bunfig.toml"
      ],
      "hasTelemetryOption": true
    },
    "metadata": {
      "costUsd": 0.004
    }
  }
}
```

A field the page does not state comes back as `null`. Each value is checked against the page text before it is returned.

## Fill a prompt

When you do not want to write a schema, send a `prompt`. The model picks the field names and returns up to 20 fields.

In the `json` format object, replace `schema` with `"prompt": "the name of the config file and where a global one goes"`. Read the resulting fields in `data.json`.

Use a `schema` when your code reads the fields by name, because a prompt can name fields differently from one call to the next.

## Read attributes

To read attribute values such as link URLs, send the `attributes` format. It uses no model and adds no charge. Each entry in `selectors` names the elements to match with a CSS `selector` and the `attribute` to read. Send 1 to 50 entries. For the `href` of each link, use `{ "type": "attributes", "selectors": [{ "selector": "a", "attribute": "href" }] }` in `formats`.

`data.attributes` has one entry for each selector you sent, with its `selector`, its `attribute` and the `values` it found. The read costs $1 per 1,000 pages. `attributes` adds nothing.

## Options

Choose CSS rules when you know the selectors, or a parser when the site already has one. Use a schema or prompt when you need fields from the page text.

| Field | Type | Default | Effect |
| - | - | - | - |
| `type` | `string` | none | `"json"`. Required. |
| `schema` | `object` | none | The fields to fill, as a JSON Schema (draft-07 or 2020-12) with `properties`. Up to 100 top-level fields and 32 KB. |
| `prompt` | `string` | none | What to pull from the page, in plain words. 1 to 10,000 characters. |
| `rules` | `object` | none | Read the page with CSS rules and no model, for no extra charge. Each field is a selector such as `"h1"` or `"a@href"`. Up to 100 fields, 5 levels deep. Not with `schema`, `prompt` or `parser`. |
| `parser` | `string` | none | Read a site with its own parser. See [Pre-built parsers](/scrape/prebuilt-parsers). |
| `options` | `object` | none | Extra inputs for a `parser`, such as `{ "page": 2 }`. |

Pydantic's `model_json_schema()` and zod's `toJSONSchema()` output work as they are. `enum`, `const`, `anyOf`, `oneOf`, nullable types, `$ref` with `$defs`, `required` and `description` are all read.

## Limits and errors

Check the format object if a request fails. If fields come back null, check that the page states them in the text we read.

- The model reads the first 50,000 characters of the page's Markdown.
- A `json` format with no `schema`, `prompt`, `rules` or `parser` returns `400 invalidRequest` with the message `formats: json needs a schema or a prompt for this page.`
- `rules` together with `schema`, `prompt` or `parser` returns `400 invalidRequest` with the message `rules cannot be combined with schema, prompt or parser`.
- If the page states none of your fields, the model fee is not charged.
