## Response

`data.results` lists a page of the hotel's reviews, each with its score, what the guest liked and disliked, room and dates.

This real response is cut to one item per list.

| Field | Type | Description |
| --- | --- | --- |
| `cursor` | string | Send it back as `cursor` for the next page. The last page has none. |
| `total` | integer | The total number of matching results, across all pages. |
| `score` | number | Upvotes minus downvotes. |
| `createdAt` | string (ISO 8601) | The creation time, in UTC. |

## Optional parameters

| Parameter | Type | Description |
| --- | --- | --- |
| `sort` | string | Booking.com's own Sort reviews by: newest, `mostRelevant` or `lowestScore` (lowest scores first). Only newest pages without gaps. The other orders change between requests, so a walk through the pages can miss reviews. One of `newest`, `mostRelevant` or `lowestScore`. Defaults to `newest`. |
| `cursor` | string | The `cursor` from the previous response. Send it back unchanged. |

## Price

Each call costs $0.0015, however many items come back. A call that fails or finds nothing is free. Top-ups of $100 or more cost less. See [Pricing](/billing).

## Pages

Each call returns one page. For the next one, send `data.cursor` back as `cursor`. The last page has no `cursor`.
