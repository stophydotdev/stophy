The `stophy` package calls the Stophy API from TypeScript, with a type for every method and result. [SDKs](/sdks) covers the API key and the defaults both SDKs share.

## Install

Run `npm install stophy` to add the client to your project.

## Scrape a page without an API key

Save this as `scrape.ts` and run it. It prints the page's title and Markdown.

```ts
import { Stophy } from "stophy";

const stophy = new Stophy();

const page = await stophy.scrape({ url: "https://example.com", formats: ["markdown"] });
console.log(page.data.metadata.title);
console.log(page.data.markdown);
```

The output starts like this.

```text
Example Domain
This domain is for use in documentation examples without needing permission. …
```

To try a search, pass `query: "bun runtime"`, `sources: ["web"]` and `limit: 3` to `stophy.search()`. Read the results in `data.web`.

`scrape`, `search`, `map` and `parse` work without an API key, up to 10 calls a minute and 50 calls a day per IP address. `parsers`, `endpoints`, `signup` and `signup.poll` need no API key. Every other method throws a `StophyError` with the code `apiKeyRequired`.

## Use an API key

Get an [API key](https://stophy.dev/signup) to call endpoints that require one. Set `STOPHY_API_KEY`, or pass the key as the `apiKey` option or as the only argument to `new Stophy()`.

Each method sends one call to the [Stophy API](/api-reference/introduction) and returns its JSON as it is. `scrape` returns `{ success, data }`, `search` returns `{ success, data }` with a list for each source, and `map` returns `{ success, links }`. Each item of `links` has a `url`, plus a `title` and a `description` when the page has them. The answers of `search`, `map` and the job starts have no cost or request id, and the SDK returns only the answer body. A scrape or a parse has its cost in `data.metadata.costUsd`, and a scrape has its id in `data.metadata.scrapeId`. `stophy.logs()` calls `GET /v1/logs`, which lists each call with its cost.

## Read a site with a parser

A parser reads a site's page and returns its data as JSON: Reddit posts, Google Maps places, Amazon products, YouTube videos and more. Send the parser's name and the page URL.

For a Reddit search page, pass `"reddit-search"` and its URL to `stophy.parsed()`. Read the result at `data.json`.

`parsed` calls `scrape` with the format `{ type: "json", parser }`. The parser name is typed, so your editor lists every parser. `await stophy.parsers()` returns each parser with the page it reads and what it returns.

Pass parser options as the third argument. For example, pass `{ page: 2 }` with a `google-maps` search URL to fetch the second page.

Paging needs an API key. See [Pre-built parsers](/scrape/prebuilt-parsers).

## Crawl a site

`crawl` answers at once with an `id`. Ask `crawl.status` for the pages.

Pass `url` and `limit: 20` to `stophy.crawl()` to read up to 20 pages. Pass the returned `id` to `crawl.status()`, then read `data`, `completed` and `total`.

`status` is `scraping` while the crawl runs. Call `crawl.status` again until it is `completed`, `failed` or `cancelled`. A status answer holds up to 100 finished pages or 2 MB. When the answer has a `next` link, send the `cursor` value from that link with the same `id` to get the rest. `crawl.cancel({ id })` stops the crawl and keeps the pages already read. A crawl and its pages are kept for 24 hours. See [Read a crawl](/crawl/async).

`batch.scrape` takes a list of URLs and works the same way, with `batch.scrape.status` and `batch.scrape.cancel`. See [Batches](/batches/overview).

## Extract fields from pages

Use `stophy.extract()` with `urls` and a `prompt` when you need fields instead of a whole page. Pass the returned `id` to `extract.result()` to read `data` and `confidence`.

`extract` answers when the fields are ready, so `extract.result` returns them at once. Results are kept for 24 hours. After that, or for an unknown `id`, `extract.result` throws a `StophyError` with the code `notFound`. See [Extract](/extract/overview).

## Handle errors

Catch errors and check `error instanceof StophyError` before you read its fields. If you pass `url: "not a url"` to `scrape`, the error code is `invalidRequest` and `retryable` is `false`. `StophyError` has `code`, `message`, `retryable`, `retryAfterSeconds`, `status`, `requestId` and `details`. The message says what went wrong and what to do next.

A call your balance cannot cover throws `insufficientCredits` with status `402` and charges nothing. Add money at [stophy.dev/billing](https://stophy.dev/billing), then send the call again.

The SDK retries eligible reads and writes. If a write may have run and the SDK cannot safely replay it, the SDK stops and sets `outcomeUnknown` on the error, even if the API marked it `retryable`. Check whether the work finished before sending a new request. If a retry would require waiting more than 60 seconds, the SDK throws with `retryAfterSeconds` set.

## Options

Pass these options to the constructor when the defaults do not fit your app.

| Option | Default | What it does |
| - | - | - |
| `apiKey` | `STOPHY_API_KEY` | Your API key |
| `baseUrl` | `STOPHY_BASE_URL`, or the Stophy API | The server to call |
| `maxRetries` | `2` | Retries per request. `0` turns retries off. |
| `retryInitialDelayMs` | `500` | The first retry wait. It doubles each time. |
| `timeoutMs` | `70000` | Time limit in milliseconds for each attempt. |
| `headers` | none | Extra headers to send with every call |
| `fetch` | the global `fetch` | A `fetch` function to use instead |

Each method also takes `signal` as its second argument to cancel the request.

## Check your account

Check your balance or recent calls before troubleshooting usage. Use `stophy.logs({ days: 7 })` to read a week of calls.

`limits` returns your balance, your rate limits and when the key expires. `usage` returns your balance and your all-time usage. `logs` returns your recent calls. All three need an API key. See [Usage](/account/usage).
