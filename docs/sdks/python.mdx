The `stophy` package calls the Stophy API from Python 3.9 or later, with a type for every method and result. [SDKs](/sdks) covers the API key and the defaults both SDKs share.

## Install

Run `pip install stophy` to add the client to your Python project.

## Scrape a page without an API key

Save this as `scrape.py` and run it. It prints the page's title and Markdown.

```python
from stophy import Stophy

stophy = Stophy()

page = stophy.scrape(url="https://example.com", formats=["markdown"])
print(page["data"]["metadata"]["title"])
print(page["data"]["markdown"])
```

The output starts like this.

```text
Example Domain
This domain is for use in documentation examples without needing permission. …
```

To try a search, pass `query="bun runtime"`, `sources=["web"]` and `limit=3` to `stophy.search()`. Read the results in `data["web"]`.

`scrape`, `search`, `map` and `parse` work without an API key, up to 10 calls a minute and 50 calls a day per IP address. `parsers`, `endpoints`, `signup` and `signup.poll` need no API key. Every other method raises a `StophyError` with the code `apiKeyRequired`.

## Use an API key

Get an API key at [stophy.dev/signup](https://stophy.dev/signup). Set it as `STOPHY_API_KEY`, or pass it in.
 You can also pass it as the `api_key` keyword when you create `Stophy`.

Each method sends one call to the [Stophy API](/api-reference/introduction) and returns its JSON as a dict. `scrape` returns `success` and `data`, `search` returns `success` and `data` with a list for each source, and `map` returns `success` and `links`. Each item of `links` has a `url`, plus a `title` and a `description` when the page has them. The answers of `search`, `map` and the job starts have no cost or request id, and the SDK returns only the answer body. A scrape or a parse has its cost in `data.metadata.costUsd`, and a scrape has its id in `data.metadata.scrapeId`. `stophy.logs()` calls `GET /v1/logs`, which lists each call with its cost.

Arguments are keyword-only and snake_case.

For async code, use `AsyncStophy`. It has the same methods, and you `await` each call.

Use `async with AsyncStophy() as client:` to close an async client when you are done. For example, `await client.map(url="https://example.com")` returns `links` with the example site's URL and title. With the synchronous client, use `with Stophy() as stophy:`.

## Read a site with a parser

A parser reads a site's page and returns its data as JSON: Reddit posts, Google Maps places, Amazon products, YouTube videos and more. Send the parser's name and the page URL.

For a Reddit search page, pass `"reddit-search"` and its URL to `stophy.parsed()`. Read the output under `data["json"]`.

`parsed` calls `scrape` with the format `{"type": "json", "parser": ...}`. The parser name is typed as `ParserName`. `stophy.parsers()` returns each parser with the page it reads and what it returns.

Pass parser options as extra keywords. For example, add `page=2` to `parsed` with the `google-maps` parser to fetch the second page.

Options can be snake_case or camelCase. Paging needs an API key. See [Pre-built parsers](/scrape/prebuilt-parsers).

## Crawl a site

`crawl` answers at once with an `id`. Ask `crawl.status` for the pages.

For example, pass `url` and `limit=20` to `stophy.crawl()`, then pass the returned `id` to `stophy.crawl.status()`. The status shows the pages in `data` and the counts in `completed` and `total`.

`status` is `scraping` while the crawl runs. Call `crawl.status` again until it is `completed`, `failed` or `cancelled`. A status answer holds up to 100 finished pages or 2 MB. When the answer has a `next` link, send the `cursor` value from that link with the same `id` to get the rest. `stophy.crawl.cancel(id=...)` stops the crawl and keeps the pages already read. A crawl and its pages are kept for 24 hours. See [Read a crawl](/crawl/async).

`stophy.batch.scrape(urls=[...])` takes a list of URLs and works the same way, with `batch.scrape.status` and `batch.scrape.cancel`. See [Batches](/batches/overview).

## Extract fields from pages

Use `stophy.extract()` with `urls` and a `prompt` when you need fields rather than the full page. Pass the returned `id` to `stophy.extract.result()` to read them again. Inspect `data` and `confidence`.

`extract` answers when the fields are ready, so `extract.result` returns them at once. Results are kept for 24 hours. After that, or for an unknown `id`, `extract.result` raises a `StophyError` with the code `notFound`. See [Extract](/extract/overview).

## Handle errors

Catch `StophyError` when your code needs to act on a failed call. For example, passing `url="not a url"` to `scrape` raises `invalidRequest` with `retryable` set to `False`. `StophyError` has `code`, `retryable`, `retry_after_seconds`, `status`, `request_id` and `details`. The message is `str(error)`. It says what went wrong and what to do next.

A call your balance cannot cover raises `insufficientCredits` with status `402` and charges nothing. Add money at [stophy.dev/billing](https://stophy.dev/billing), then send the call again.

The SDK retries eligible reads and writes. If a write may have run and the SDK cannot safely replay it, the SDK stops and sets `outcome_unknown` on the exception, even if the API marked it `retryable`. Check whether the work finished before sending a new request. If a retry would require waiting more than 60 seconds, the SDK raises with `retry_after_seconds` set.

## Options

Set these options when you create the client. Change the timeout if an attempt needs more than 70 seconds.

| Option | Default | What it does |
| - | - | - |
| `api_key` | `STOPHY_API_KEY` | Your API key |
| `base_url` | `STOPHY_BASE_URL`, or the Stophy API | The server to call |
| `max_retries` | `2` | Retries per request. `0` turns retries off. |
| `retry_initial_delay` | `0.5` | The first retry wait in seconds. It doubles each time. |
| `timeout` | `70.0` | Time limit in seconds for each attempt. |
| `headers` | none | Extra headers to send with every call |

## Check your account

Check your balance or recent calls before troubleshooting usage. Use `stophy.logs(days=7)` to read a week of calls.

`limits` returns your balance, your rate limits and when the key expires. `usage` returns your balance and your all-time usage. `logs` returns your recent calls. All three need an API key. See [Usage](/account/usage).
