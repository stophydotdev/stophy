Run `stophy` with a source and a command, and it prints what comes back. It works in your terminal, your scripts and any agent that runs shell commands.

```bash
curl -fsSL https://stophy.dev/install | bash
stophy google search "postgres jsonb index"
```

No account, no login.

```text
1. Documentation: 18: 8.14. JSON Types - PostgreSQL
   https://www.postgresql.org/docs/current/datatype-json.html
2. Indexing JSONB in Postgres | Crunchy Data Blog
   https://www.crunchydata.com/blog/indexing-jsonb-in-postgres
```

The installer puts the binary in `~/.local/bin`. On Windows, run this in PowerShell.

```powershell
irm https://stophy.dev/install.ps1 | iex
```

With Node.js 20 or later, `npm install -g @stophy/cli` works too.

## Set up your agent

```bash
npx -y @stophy/cli init --all
```

This logs you in, adds Stophy's skills to your coding agents, and adds the Stophy MCP server.

## Log in

Without a login you can run the commands marked `free` in `stophy endpoints`. To run the rest, log in with your browser.

```bash
stophy login --browser
```

The CLI prints a code and opens stophy.dev. Check that the page shows the same code, then approve it. On a server with no browser, open the printed link on any other device. The CLI logs in once you approve there.

To use an API key instead, pass it to `login` or set it in the environment.

```bash
stophy login --api-key st_...
export STOPHY_API_KEY="st_..."
```

`stophy logout` logs out and revokes this computer's key.

## Make a call

Name the source, then the command.

```bash
stophy youtube search "bun runtime"
stophy reddit subreddit rust
stophy google maps search --query dentist --location Berlin
stophy youtube transcript --videoUrl https://youtu.be/M4TufsFlv_o
```

To point at one thing, use its link or its id with the matching option, like `--videoUrl` or `--videoId`. Send one, not both.

`stophy <source> --help` lists what a source can do, and `stophy <source> <command> --help` lists every option. A value the option doesn't take stops the CLI before it calls Stophy, and it prints the values that work.

## Read the output

Lists print one row per result with its title and link. Other results print as `name: value` lines. Add `--json` for the data as JSON, with the cost on stderr. `--raw` prints the full response, including `requestId`.

```bash
stophy reddit search "bun runtime" --json
```

`-o <path>` writes the output to a file.

```bash
stophy youtube search "bun runtime" --json -o results.json
```

## Page through results

When a command has more, its output ends with a `cursor`. Pass it back with `--cursor`. This needs a login.

```bash
stophy reddit search "bun runtime" --cursor "<cursor from the last output>"
```

Commands for sites with numbered pages take `--page`, like `stophy google search "bun runtime" --page 2`. See [Page through results](/guides/paging).

## Use it in a script

A failed call exits non-zero and writes its message to stderr. The message ends with the request id, and with `Retry after Ns.` when the API says to wait. The CLI does not retry for you.

```bash
if ! stophy reddit search "bun runtime" --json -o out.json 2>err.txt; then
  cat err.txt
  exit 1
fi
```

## Check your usage

```bash
stophy status
stophy usage
stophy logs --days 7
```

## Commands

| Command | What it does |
| --- | --- |
| `stophy init` | Set up Stophy in your coding agents |
| `stophy login` | Log in with your browser or an API key |
| `stophy logout` | Log out and revoke this computer's key |
| `stophy <source> <command>` | Get data, for example `stophy youtube search` |
| `stophy endpoints [word]` | List every command and its cost |
| `stophy describe <id>` | Show one command's options, cost and an example |
| `stophy status` | Show your login, balance and CLI version |
| `stophy usage` | Show your balance and all-time usage |
| `stophy logs` | Show your recent requests |
| `stophy doctor` | Check your install, login and connection |
| `stophy version` | Show the CLI version |
