Use a monitor when you need to know what changes after the first read. We check your pages or search on a schedule and record what changed. It bills for every page it reads on every check, so a monitor keeps costing money until you pause or delete it.

## Make a request

Get an API key in the [Quickstart](/quickstart). Monitors need an API key. This request watches one page once a week and sends a webhook after each check.

<CodeGroup>
```bash cURL
curl -X POST https://api.stophy.dev/v1/monitor \
  -H "Authorization: Bearer $STOPHY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Example home page",
    "targets": [{ "type": "scrape", "urls": ["https://example.com"] }],
    "schedule": { "text": "weekly" },
    "webhook": {
      "url": "https://example.com/stophy-hook",
      "events": ["monitor.page", "monitor.check.completed"],
      "metadata": { "project": "docs" }
    }
  }'
```
```typescript TypeScript

console.log(data.id, data.nextRunAt);
```
```python Python

```

`name`, `targets` and `schedule` are required. Creating a monitor is free.

## Read the response

Save `data.id` to manage the monitor and read its checks. The response also includes the ID at the top level.

```json
{
  "success": true,
  "data": {
    "id": "mon_hpJ-ZKa4FJLr4h1m",
    "name": "Example home page",
    "status": "active",
    "schedule": { "cron": "0 0 * * 1", "timezone": "UTC", "everySeconds": null },
    "nextRunAt": "2026-11-17T18:19:27.540Z",
    "estimatedCostUsdPerMonth": 0.004,
    "checks": 0,
    "costUsd": 0
  },
  "id": "mon_hpJ-ZKa4FJLr4h1m",
  "costUsd": 0
}
```

The first check starts at once and usually within a minute. For page targets, it keeps the first read as a baseline and reports no change. A search target can report new results on its first check. Later checks compare with the last read. In this example the check ran 26 seconds after the monitor was created and found the page `new`.

| Field | What it holds |
| - | - |
| `status` | `active` or `paused`. A paused monitor reads nothing and costs nothing. |
| `pausedReason` | Why Stophy paused it, such as `insufficientCredits` when your balance ran out. |
| `schedule` | A `cron` expression or `everySeconds`, and the `timezone`. See [Schedules](/monitors/schedules). |
| `nextRunAt`, `lastRunAt` | When the next scheduled check is due, and when the last one ran. `nextRunAt` is `null` while paused. |
| `currentCheckId` | The check that is queued or running now, or `null`. |
| `targets` | What the monitor watches. See [Targets](/monitors/targets). |
| `goal`, `judgeEnabled` | What matters to you, and whether each changed page is judged against it. |
| `retentionDays` | How many days checks, diffs and snapshots are kept, 1 to 365. 30 by default. |
| `estimatedCostUsdPerMonth` | Pages watched times the checks in 30 days, at $1 per 1,000 pages. `estimatedCreditsPerMonth` holds the same amount in steps of $0.002. |
| `webhook` | Where Stophy sends events. See [Webhooks](/monitors/webhooks). |
| `notification` | The email settings. See [Webhooks](/monitors/webhooks#get-an-email-instead). |
| `checks`, `costUsd` | How many checks have run and what they cost so far. `creditsUsed` holds the same amount in steps of $0.002. |

`urls`, `interval`, `formats`, `changeTracking`, `nextCheckAt` and `lastCheckAt` repeat other fields for older clients.

## What a monitor can watch

Choose the target based on whether you know the URLs or want the monitor to find them.

| Target `type` | What it watches | Guide |
| - | - | - |
| `scrape` | Up to 100 pages you list | [Targets](/monitors/targets) |
| `crawl` | The pages under a start page, found again on every check | [Targets](/monitors/targets#crawl-targets) |
| `search` | New results for up to 12 queries | [Targets](/monitors/targets#search-targets) |

## Manage a monitor

Use the monitor ID to change its settings or read what it found.

| Call | What it does | Guide |
| - | - | - |
| `GET /v1/monitor` | Lists your monitors, newest first. Send `limit` up to 100 (20 by default), and `cursor` from `next` for the next part. | This page |
| `GET /v1/monitor/{id}` | Reads one monitor. | This page |
| `PATCH /v1/monitor/{id}` | Changes the name, schedule, targets, goal, webhook or email, or pauses and resumes it. | [Schedules](/monitors/schedules) |
| `DELETE /v1/monitor/{id}` | Deletes the monitor and stops its checks, so it stops billing. | This page |
| `POST /v1/monitor/{id}/run` | Checks now, outside the schedule. | [Schedules](/monitors/schedules#run-a-check-now) |
| `GET /v1/monitor/{id}/checks`, `GET /v1/monitor/{id}/changes` | Reads what each check found. | [Checks and changes](/monitors/checks-and-changes) |
| `GET /v1/monitor/limits`, `GET /v1/monitor/usage` | Reads your allowance and what monitors cost. | [Limits and errors](/monitors/limits-and-errors) |

Reading, listing, updating and deleting are free. A request for a monitor that does not exist, or that belongs to another account, returns `404 notFound`.

## List and delete

List monitors to find an ID or check which ones are still active. For example, `GET /v1/monitor?limit=1` returns one monitor in `data`. Send the returned `next` as `cursor` for the next part. `next` is `null` on the last part, and `data` is empty if you have no monitors.

When you no longer need a monitor, send `DELETE /v1/monitor/{id}`. The monitor stops checking and the call returns `success: true` with `costUsd: 0`.

## Before you rely on alerts

Check that the first read worked and that your receiver can handle deliveries.

- The first check completed, and `checks` on the monitor is 1 or more. See [Checks and changes](/monitors/checks-and-changes).
- `goal` says what matters, so a change that does not matter is marked as such. See [Targets](/monitors/targets#goal-and-judge).
- Your receiver verifies the signature and ignores an event it has already seen. See [Webhooks](/webhooks).
- You know when it stops: the monitor pauses itself when your balance runs out, and sends `monitor.failed` if you subscribed to it.

## Price

Estimate the cost from the number of pages and checks, even if nothing changes.

Each page read costs $1 per 1,000 pages, which is $0.001, on every check, including the first. A page that cannot be read costs nothing. A page that is gone, with a 404 or 410 status, is charged once when it is first found gone.

A `goal` adds $1 per 1,000 pages for each changed page it judges. `json` comparison adds $3 per 1,000 pages when it returns fields. A search target costs $1 per 1,000 searches of up to 10 results on every check. A monitor of one page checked daily costs about $0.03 a month. Calls that read, list, change, pause, resume and delete monitors cost nothing. See [Pricing](/account/pricing).

## Choose another API

Use a one-off call if you do not need checks to repeat.

- [Scrape](/scrape/overview) reads one page now. With [change tracking](/scrape/change-tracking) it compares with your last read.
- [Crawl](/crawl/overview) reads every page of a site once, in the background.
- [Batches](/batches/overview) read a list of URLs once, in the background.
- [Search](/search/overview) finds pages from a query once.
- [Webhooks](/webhooks) explains the signature and delivery of every call Stophy makes to you.
