description: "Watch pages, a site section or a search on a schedule. Each change comes with its diff, by signed webhook or by reading checks. Needs an API key."

A monitor checks your targets on a schedule and records what changed. It is charged for every page it reads on every check, so it keeps costing until you pause or delete it. See [Pricing](/account/pricing). Monitors need an API key. See the [Quickstart](/quickstart).

`name`, `targets` and `schedule` are required. Creating a monitor is free. The response, cut to the main fields:

```json
{
  "success": true,
  "data": {
    "id": "mon_hpJ-ZKa4FJLr4h1m",
    "name": "Example home page",
    "status": "active",
    "schedule": { "cron": "0 0 * * 1", "timezone": "UTC", "everySeconds": null },
    "nextRunAt": "2026-11-17T18:19:27.540Z",
    "checks": 0
  },
  "id": "mon_hpJ-ZKa4FJLr4h1m"
}
```

The first check starts at once, usually within a minute. For page targets it records a baseline and reports no change. A search target can report results on its first check.

| Field | Holds |
| --- | --- |
| `status` | `active` or `paused`. A paused monitor reads nothing and costs nothing. |
| `pausedReason` | Why Stophy paused it, such as `insufficientCredits`. |
| `nextRunAt`, `lastRunAt`, `currentCheckId` | The next due check (`null` while paused), the last one, and the one queued or running now. |
| `targets`, `goal`, `judgeEnabled` | See [Targets](/monitors/targets). |
| `retentionDays` | Days checks, diffs and snapshots are kept, 1 to 365, default 30. |
| `webhook`, `notification` | See [Checks, changes and webhooks](/monitors/checks-and-changes#webhooks). |
| `estimatedCostUsdPerMonth` | Pages watched times checks in 30 days. |
| `checks`, `costUsd` | Checks run and what they cost so far. |

`urls`, `interval`, `formats`, `changeTracking`, `nextCheckAt` and `lastCheckAt` repeat other fields for older clients.

## Manage a monitor

All of these are free. A monitor that does not exist, or belongs to another account, returns `404 notFound`.

| Call | Does |
| --- | --- |
| `GET /v1/monitor` | Lists newest first. `limit` up to 100 (default 20), and `next` as `cursor` for the next part. |
| `GET /v1/monitor/{id}` | Reads one. |
| `PATCH /v1/monitor/{id}` | Changes `name`, `schedule`, `targets`, `goal`, `webhook`, `notification`, `retentionDays` or `status`. Send at least one field. It replaces `targets` and `webhook` as a whole. |
| `DELETE /v1/monitor/{id}` | Deletes it and stops billing. |
| `POST /v1/monitor/{id}/run` | Queues a check now. |
| `GET /v1/monitor/limits`, `GET /v1/monitor/usage` | Your allowance, and cost per monitor. |

## Schedule

Send `schedule` on create or `PATCH`. Send `text` or `cron`, not both. A daily time comes back as a `cron` expression.

```json
{ "schedule": { "text": "daily at 9:00", "timezone": "Europe/Ljubljana" } }
```

| Field | Effect |
| --- | --- |
| `cron` | Five fields, minute to weekday. Runs no closer than 5 minutes. `0 0 1 * *` is fine. |
| `text` | Plain words, below. |
| `timezone` | An IANA name, default `UTC`. Sets what `daily at 9:00` and a cron expression mean. |

| `text` | Runs |
| --- | --- |
| `every 30 minutes` | At least `every 5 minutes`. A number that divides 60 keeps to the clock. Another number, such as 7, counts from the last check. |
| `every 15 minutes starting at :07` | At minutes 7, 22, 37 and 52. |
| `hourly`, `every hour` | At the start of every hour. |
| `every 2 hours` | A number that divides 24 keeps to the clock. Another counts from the last check. |
| `daily`, `daily at 9:00`, `daily at 5:30 PM` | Every day, at midnight when no time is given. |
| `weekly` | Monday at midnight. |

The older `interval` field takes seconds, or `30m`, `6h`, `1d`. Use it only with `url` and `urls`.

A check starts at its time or within about a minute. Checks of one monitor never overlap: a check that falls due while the last one runs is recorded as `skipped_overlap` and is free.

## Run, pause and resume

`POST /v1/monitor/{id}/run` queues a check outside the schedule, which does not move. It returns the queued check, with `status: "queued"`, `trigger: "manual"` and `estimatedCostUsd`. Read the result with `GET /v1/monitor/{id}/checks/{checkId}`. A manual check costs the same as a scheduled one.

`PATCH` with `"status": "paused"` stops checks and keeps history. `"status": "active"` resumes with a check at once. Changing the schedule of a paused monitor keeps it paused.

Reasons a monitor stops or fails:

- Your balance ran out. It pauses with `pausedReason: "insufficientCredits"` and sends `monitor.failed` if you subscribed. Add funds, then resume.
- A page cannot be read. The monitor keeps running and the page is `error` and free. After 5 checks in a row fail on the same page, `monitor.failed` is sent once.
- Every page failed for lack of balance. The check is `skipped_no_credits`.

## Limits

`GET /v1/monitor/limits` returns these as `monitors`, `pages`, `perMonitor` and `intervalSeconds`. Rate limits are on [Rate limits](/production/rate-limits).

| Limit | Value |
| --- | --- |
| Monitors per account | 25. Paused ones count. |
| Pages watched across all monitors | 1,000. Paused ones count. A crawl target counts its `limit`, a search target its `maxResults`. |
| Pages in one scrape target | 100 |
| Targets in one monitor | 50 |
| Time between checks | 5 minutes to 30 days |
| Name | 1 to 256 characters |
| Checks and changes kept | The last 1,000 of each, within `retentionDays` |

`GET /v1/monitor/usage` totals what checks cost per monitor, highest first, including deleted ones (`deleted: true`). Send `from` and `to` as an ISO date or time, with `to` excluded and a window of at most 366 days. The default is the last 30 days.

## Errors

Codes are on [Errors](/api-reference/errors). Every message below is `400 invalidRequest` unless noted. A failed call is free.

| `error` or code | Fix |
| --- | --- |
| `You can run 25 monitors. Delete one to add another.` | Delete one. Pausing does not free a slot. |
| `Your monitors can watch 1,000 pages in total, and N are in use.` | Watch fewer pages. |
| `schedule: the minimum interval is 5 minutes`, `the maximum interval is 30 days` | Change the schedule. |
| `schedule.text: could not read "every banana". Try every 30 minutes, hourly, ...` | Use a form above. |
| `schedule.cron: send five fields, minute to weekday` | Fix the expression. |
| `schedule.timezone: Mars/Base is not an IANA timezone ...` | Use an IANA name. |
| `schedule: Send cron or text in schedule, not both`, `schedule: send cron or text` | Send exactly one, and a schedule on create. |
| `409 checkRunning` | A check is queued or running. Wait, then run again. |
| `409 invalidRequest`, `This monitor is paused. ...` | Send `{ "status": "active" }`, then run again. |

Target and webhook errors are on [Targets](/monitors/targets#limits-and-errors) and [Checks, changes and webhooks](/monitors/checks-and-changes#limits-and-errors).
