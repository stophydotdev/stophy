Choose a target based on what you know: use `scrape` for fixed URLs, `crawl` to discover pages under a start page, or `search` to watch a query. It holds 1 to 50 targets, and each has a `type` of `scrape`, `crawl` or `search`. One monitor can mix types, and every check reads every target.

## Make a request

Start with a scrape target when you know the page address. Get an API key in the [Quickstart](/quickstart). This request watches one page and judges each change against a goal. The page returns a new identifier on every read, so checks after the baseline can show how a change looks.

<CodeGroup>
```bash cURL
curl -X POST https://api.stophy.dev/v1/monitor \
  -H "Authorization: Bearer $STOPHY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Page that changes",
    "targets": [{ "type": "scrape", "urls": ["https://httpbin.org/uuid"] }],
    "schedule": { "cron": "0 0 1 * *" },
    "goal": "Tell me whenever the uuid changes.",
    "webhook": {
      "url": "https://example.com/stophy-hook",
      "events": ["monitor.page", "monitor.check.completed"]
    }
  }'
```

## Scrape targets

A scrape target lists the pages to read on every check. An address sent twice is read once.

| Field | Type | Default | Effect |
| - | - | - | - |
| `type` | `string` | none | `"scrape"`. Required. |
| `urls` | `array of string` | none | 1 to 100 public page addresses. Required. |
| `id` | `string` | made for you | A stable name for this target, 1 to 64 characters. Pages in a check say which target they came from. |
| `scrapeOptions` | `object` | `{}` | How each page is read. See below. |

### Scrape options

`scrapeOptions` takes the same fields as [Scrape](/scrape/overview), except `url`. A monitor always reads the page live, so it ignores `maxAge` and `minAge`. `zeroDataRetention` is refused, because a monitor keeps a snapshot of each page to compare with the next.

`formats` says what to compare. The first of `markdown`, `html`, `rawHtml` and `links` is compared, and `markdown` is the default. A page counts as changed when that text differs from the last read.

To compare fields instead of text, add a `changeTracking` format or a `json` format with a `schema` or a `prompt`, as in [Change tracking](/scrape/change-tracking) and [JSON](/scrape/json). The `modes` of `changeTracking` are `git-diff`, which returns the text diff, and `json`, which returns each field before and after. With only `json`, a page whose text changed but whose fields did not is `same`. `json` adds $3 per 1,000 pages when it returns fields.

## Crawl targets

Use a crawl target when the list of pages under a start page can change. Every check finds the pages under it again and reads each one, so a page that appears later shows up as a `new` change.

Set `"crawlOptions": { "limit": 2, "maxDepth": 1 }` to read at most two pages one path level below the start. When you save the target, the response includes its ID and default options.

The check that ran afterwards read one page, because the site has no other page under that address, and cost $0.001.

| `crawlOptions` field | Type | Default | Effect |
| - | - | - | - |
| `limit` | `number` | 100 | The most pages to read on each check, 1 to 500. The monitor is billed for the pages it finds, up to this number. |
| `maxDepth` | `number` | 3 | How many path levels below the start page to go, 0 to 10. `maxDiscoveryDepth` is the same field. |
| `includePaths`, `excludePaths` | `array of string` | `[]` | Up to 100 regular expressions each. A page is kept when its path matches an include pattern, or when there are none, and no exclude pattern. |
| `regexOnFullURL` | `boolean` | `false` | Match the patterns against the whole address instead of the path. |
| `crawlEntireDomain` | `boolean` | `false` | Also follow pages that are not under the start page's path. |
| `allowSubdomains` | `boolean` | `false` | Include pages on subdomains. |
| `ignoreQueryParameters` | `boolean` | `true` | Treat addresses that differ only by query string as one page. |
| `sitemap` | `string` | `include` | `skip` ignores the sitemap, `include` uses it with the links, `only` uses only the sitemap. |

A crawl target takes `scrapeOptions` too. If a check finds no pages, it fails and says so in `error`.

## Search targets

Use a search target to find new results for a query on every check. It does not take a page snapshot, so there is no baseline. We can report a meaningful result the first time we find it.

For example, set `"searchWindow": "7d"` and `"maxResults": 3` to look at up to three results from the past week. One check with those options cost $0.004: $0.001 for the search and $0.001 for each result the judge read.

| Field | Type | Default | Effect |
| - | - | - | - |
| `queries` | `array of string` | none | 1 to 12 search queries of up to 256 characters. Required. |
| `searchWindow` | `string` | `24h` | Only results published within `5m`, `15m`, `1h`, `6h`, `24h` or `7d`. A window shorter than `24h` returns the results of the past day. |
| `maxResults` | `number` | 10 | How many results to look at on each check, 1 to 50, merged and deduplicated across the queries. |
| `includeDomains`, `excludeDomains` | `array of string` | `[]` | Up to 50 domains each, such as `example.com`. A domain includes its subdomains. |

A search target needs a `goal`, or `judgeEnabled: false`. Without either, the call returns `400 invalidRequest` with `goal: a search target needs a goal to judge results against, or judgeEnabled set to false`. A result the judge finds meaningful is reported as `new`. A result it finds not meaningful is marked `ignored` and is not looked at again. A result you have already been told about is `already_seen`. See [Checks and changes](/monitors/checks-and-changes#search-results).

## Goal and judge

Write a `goal` to mark changes that matter to you. Use plain words, up to 2,000 characters. With a goal, a model judges every changed page against it. `judgeEnabled: false` turns the judge off while keeping the goal.

Read `judgment` in the page result or webhook. `reason` explains whether the change was `meaningful`. `meaningfulChanges` lists specific changes with their `type`, `before`, `after` and `reason`.

`confidence` is `high`, `medium` or `low`. A change the judge calls not meaningful is still recorded and still sent, with `meaningful: false`, so you decide what to do with it. If the judge cannot decide, `judgment` is `null` and the page is not charged for it. Judging adds $1 per 1,000 pages for each changed page it reads.

## Update targets

When you add or remove a target, use `PATCH /v1/monitor/{id}`. It replaces `targets` as a whole, so send every target you want to keep. You can also change `goal` and `judgeEnabled` in the same call.

- A page you keep stays compared with its last snapshot.
- A page you add to a scrape target is read for the first time on the next check, which only records it as `new` and sends no event.
- A page you remove is no longer read or billed.

## Limits and errors

Check the page and target limits before expanding a monitor.

- A monitor takes at most 50 targets and 100 pages in one scrape target. Your account takes 25 monitors and 1,000 pages in all. See [Limits and errors](/monitors/limits-and-errors).
- An address that is not a public website returns `400 invalidRequest` with `targets.0.urls.0: Expected a public website URL`.
- `zeroDataRetention` inside `scrapeOptions` returns `400 invalidRequest` with `zeroDataRetention is not available for monitors, which keep a snapshot to compare`.
- Send `targets` and `schedule` together. The older fields `url`, `urls`, `interval`, `formats` and `changeTracking` still work on their own: `url` or `urls` for the pages, `interval` for seconds or text such as `30m`, `6h` or `1d`, and `changeTracking` for the compare modes. Sending them together with `targets` or `schedule` returns `400 invalidRequest`.
