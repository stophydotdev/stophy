Make your first Stophy request and read the result. To have a coding agent do the setup, use the [Agent quickstart](/agent-quickstart).

## Try it without an API key

Search, scrape, map and parse work without an API key, up to 10 calls a minute and 50 calls a day per IP address. To try a page from cURL, send `POST /v1/scrape` with `"url": "https://example.com"`, `"formats": ["markdown"]` and `"onlyMainContent": true`. Leave out the `Authorization` header. The page text comes back in `data.markdown`, and `data.metadata.costUsd` is `0`.

Paging, crawl, batches, extract, agent, browsers and monitors need an API key. See [Rate limits](/production/rate-limits) for the free limits.

## 1. Get an API key

Sign up at [stophy.dev/signup](https://stophy.dev/signup) with GitHub or Google. A new account starts with $2 to spend, with no card. Create a key and keep it as `STOPHY_API_KEY` in your secret store or your project's `.env` file, where your code reads it.

Keep the key on your server. Never commit it or put it in browser code. [API keys](/account/api-keys) covers revoking a key. An agent can also request a key for you to approve. See the [Agent quickstart](/agent-quickstart).

## 2. Choose a client

If you use cURL, you can go straight to the request. For TypeScript, run `npm install stophy`. For Python, run `pip install stophy`. Both [SDKs](/sdks) add types and retries and read `STOPHY_API_KEY` from your environment.

## 3. Make a request

This request searches the web for `bun runtime` and returns three results. A search of up to 10 results costs $0.001.

<CodeGroup>
```bash cURL
curl -X POST https://api.stophy.dev/v1/search \
  -H "Authorization: Bearer $STOPHY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "bun runtime",
    "sources": ["web"],
    "limit": 3
  }'
```
```typescript TypeScript
import { Stophy } from "stophy";

const stophy = new Stophy();

const { data } = await stophy.search({
  query: "bun runtime",
  sources: ["web"],
  limit: 3,
});
console.log(data?.web?.map((result) => result.url));
```
```python Python
from stophy import Stophy

stophy = Stophy()

body = stophy.search(
    query="bun runtime",
    sources=["web"],
    limit=3,
)
print([result["url"] for result in body["data"]["web"]])
```
</CodeGroup>

## 4. Check the result

Read `data.web` for the ranked results. Each result has a URL, title, description and position when those fields are available. `costUsd` is what the call cost in dollars. Empty fields are left out.

```json
{
  "success": true,
  "data": {
    "web": [
      {
        "url": "https://github.com/oven-sh/bun",
        "description": "At its core is the Bun runtime, a fast JavaScript runtime designed as a drop-in replacement for Node.js.",
        "position": 1
      }
    ]
  },
  "id": "31fb1c5e-c206-443e-9274-c8d0bf75002c",
  "costUsd": 0.001,
  "requestId": "31fb1c5e-c206-443e-9274-c8d0bf75002c"
}
```

A failed call has `success: false`, an `error` that says what to do and a `code`. It costs nothing. See [Troubleshooting](/production/troubleshooting).

## Read a site as JSON

Use a [parser](/scrape/prebuilt-parsers) when you want a site's own fields instead of page text. For a Reddit search URL, send `"formats": [{ "type": "json", "parser": "reddit-search" }]` to scrape. The posts come back in `data.json.results` with a `cursor` for the next page.

## Crawl a site

Use [Crawl](/crawl/overview) when you want us to find and read pages starting from one URL. Starting a crawl is free. Reading pages costs $1 per 1,000. A page that returns a 404 or 410 costs nothing.

Start the job with `POST /v1/crawl` and a URL. Save the returned `id` and poll `GET /v1/crawl/{id}` about every 2 seconds until `status` is no longer `scraping`. Send `"formats": ["markdown", "links"]` in `scrapeOptions` if you want links as well as the default Markdown. A status response holds up to 100 finished pages or 2 MB. If it has `next`, call that URL for the rest. See [Read a crawl](/crawl/async).

## Scrape many pages

Use a [batch](/batches/overview) when you already have the URLs. Send them as `urls` to `POST /v1/batch/scrape`. Save the returned job `id` and `url`. Poll `GET /v1/batch/scrape/{id}` about every 2 seconds until `status` is `completed`. Each page in `data` has the same shape as a scrape response.

## Try another API

Every endpoint uses the same API key and the same `Authorization` header. Send one of these, then follow its guide for options.

| API | Send | Guide |
| - | - | - |
| Scrape, other formats | Add `links`, `screenshot`, `summary` or `json` to `formats` | [Scrape](/scrape/overview) |
| Map | `POST /v1/map` with `url` | [Map](/map/overview) |
| Crawl | `POST /v1/crawl` with `url` and `limit` | [Crawl](/crawl/overview) |
| Batches | `POST /v1/batch/scrape` with `urls` | [Batches](/batches/overview) |
| Search | `POST /v1/search` with `query` | [Search](/search/overview) |
| Extract | `POST /v1/extract` with `urls` and `prompt` or `schema` | [Extract](/extract/overview) |
| Agent | `POST /v1/agent` with `prompt` | [Agent](/agent/overview) |
| Parse | `POST /v1/parse` with a file | [Parse](/parse/overview) |
| Browser sessions | `POST /v1/browser` | [Browser sessions](/browser/overview) |
| Browser tasks | `POST /v1/browser/task` with `url` and `goal` | [Browser tasks](/browser/tasks) |
| Monitors | `POST /v1/monitor` with `targets` and a `schedule` | [Monitors](/monitors/overview) |
