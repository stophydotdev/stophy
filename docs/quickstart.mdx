Make your first Stophy request and read the result. To have a coding agent do the setup, use the [Agent quickstart](/agent-quickstart).

## Try it without an API key

Search, scrape, map and parse work without an API key, up to 10 calls a minute and 50 calls a day per IP address. This request needs only cURL.

```bash
curl -X POST https://api.stophy.dev/v1/scrape \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com","formats":["markdown"],"onlyMainContent":true}'
```

Paging, crawl, batches, extract, agent, browsers and monitors need an API key. See [Rate limits](/production/rate-limits) for the free limits.

## 1. Get an API key

Sign up at [stophy.dev/signup](https://stophy.dev/signup) with GitHub or Google. A new account starts with $2 to spend, with no card. Create a key and keep it as `STOPHY_API_KEY` in your secret store or your project's `.env` file, where your code reads it.

Keep the key on your server. Never commit it or put it in browser code. [API keys](/account/api-keys) covers revoking a key. An agent can also request a key for you to approve. See the [Agent quickstart](/agent-quickstart).

## 2. Choose a client

cURL needs no install. The TypeScript and Python examples below use the [SDKs](/sdks), which add types and retries and read `STOPHY_API_KEY` from your environment.

<CodeGroup>
```bash TypeScript
npm install stophy
```
```bash Python

```
</CodeGroup>

## 3. Make a request

This request searches the web for `bun runtime` and returns three results. A search of up to 10 results costs $0.001.

<CodeGroup>
```bash cURL
curl -X POST https://api.stophy.dev/v1/search \
  -H "Authorization: Bearer $STOPHY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "bun runtime",
    "sources": ["web"],
    "limit": 3
  }'
```
```typescript TypeScript
import { Stophy } from "stophy";

const stophy = new Stophy();

const { data } = await stophy.search({
  query: "bun runtime",
  sources: ["web"],
  limit: 3,
});
console.log(data?.web?.map((result) => result.url));
```
```python Python
from stophy import Stophy

stophy = Stophy()

body = stophy.search(
    query="bun runtime",
    sources=["web"],
    limit=3,
)
print([result["url"] for result in body["data"]["web"]])
```
</CodeGroup>

## Read a site as JSON

To get a site's own data, send its page to scrape with a [parser](/scrape/prebuilt-parsers). This call reads a Reddit search.

```bash
curl -X POST https://api.stophy.dev/v1/scrape \
  -H "Authorization: Bearer $STOPHY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://www.reddit.com/search/?q=web+scraping&sort=top&t=year",
    "formats": [{ "type": "json", "parser": "reddit-search" }]
  }'
```

The posts come back in `data.json.results`, with a `cursor` for the next page. This real response is cut to one post.

```json
{
  "success": true,
  "data": {
    "json": {
      "results": [
        {
          "id": "1rxxkol",
          "title": "What's else in this list?",
          "community": { "name": "PythonLearning", "url": "https://www.reddit.com/r/PythonLearning/" },
          "publishedAt": "2026-03-19T11:13:15.803Z",
          "likes": 1230,
          "comments": 43
        }
      ],
      "cursor": "MjQ="
    }
  },
  "costUsd": 0.001
}
```

## Crawl a site

Crawl reads many pages in the background. Starting is free, and each page costs $1 per 1,000. A page that comes back with a 404 or 410 status costs nothing. Start it, poll about every 2 seconds until `status` is no longer `scraping`, then read the pages.

```bash
ID=$(curl -s -X POST https://api.stophy.dev/v1/crawl \
  -H "Authorization: Bearer $STOPHY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://bun.com/docs","limit":3}' | jq -r .id)

until [ "$(curl -s https://api.stophy.dev/v1/crawl/$ID -H "Authorization: Bearer $STOPHY_API_KEY" | jq -r .status)" != scraping ]; do sleep 2; done

curl -s https://api.stophy.dev/v1/crawl/$ID -H "Authorization: Bearer $STOPHY_API_KEY" | jq '{status, completed, pages: [.data[].metadata.url], next}'
```

```json
{
  "status": "completed",
  "completed": 3,
  "pages": [
    "https://bun.com/docs",
    "https://bun.com/docs/bundler",
    "https://bun.com/docs/bundler/bytecode"
  ],
  "next": null
}
```

Send `scrapeOptions.formats` to get more than `markdown`, for example `["markdown","links"]`. A status answer holds up to 100 finished pages or 2 MB. If it has `next`, call that URL for the rest. See [Crawl](/crawl/overview) and [Read a crawl](/crawl/async).

## Scrape many pages

A batch takes a list of URLs and works the same way. Poll `https://api.stophy.dev/v1/batch/scrape/<id>` about every 2 seconds until `status` is `completed`. Each page in `data` has the same shape as a scrape.

```bash
curl -X POST https://api.stophy.dev/v1/batch/scrape \
  -H "Authorization: Bearer $STOPHY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"urls":["https://bun.com/docs/runtime/bunfig","https://bun.com/docs/runtime/env"]}'
```

The answer holds the job `id` and its `url`. See [Batches](/batches/overview).

## Try another API

Every endpoint uses the same API key and the same `Authorization` header. Send one of these, then follow its guide for options.

| - | - | - |

| Search | `POST /v1/search` with `query` | [Search](/search/overview) |
| Extract | `POST /v1/extract` with `urls` and `prompt` or `schema` | [Extract](/extract/overview) |

| Browser sessions | `POST /v1/browser` | [Browser sessions](/browser/overview) |
| Browser tasks | `POST /v1/browser/task` with `url` and `goal` | [Browser tasks](/browser/tasks) |
| Monitors | `POST /v1/monitor` with `targets` and a `schedule` | [Monitors](/monitors/overview) |
