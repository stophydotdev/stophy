Build a search index from a docs section without losing where each passage came from. Crawl the section, split pages at headings and keep the URL on each chunk so your app can link to the source.

You need an API key in `STOPHY_API_KEY`. See the [Quickstart](/quickstart). The TypeScript and Python examples use the SDK: `npm install stophy` or `pip install stophy`. The run on this page read 3 pages and cost $0.003.

## 1. Crawl the section

Start with the URL of the section you want to index. Crawl follows links from that page and reads what it finds within your limit. Starting is free, and each page is charged when it finishes. This request stops after 3 pages, which is enough to build and check the pipeline. Raise `limit` for the whole section.

<CodeGroup>
```bash cURL
curl -X POST https://api.stophy.dev/v1/crawl \
  -H "Authorization: Bearer $STOPHY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://bun.com/docs/runtime",
    "limit": 3
  }'
```
```typescript TypeScript
import { Stophy } from "stophy";

const stophy = new Stophy();

const { id } = await stophy.crawl({
  url: "https://bun.com/docs/runtime",
  limit: 3,
});
console.log(id);
```
```python Python
from stophy import Stophy

stophy = Stophy()

result = stophy.crawl(
    url="https://bun.com/docs/runtime",
    limit=3,
)
print(result["id"])
```
</CodeGroup>

Save the `id` from the start response. Its `url` points to the status call, and `costUsd` is $0 at this point.

To keep a crawl to one part of a site, set `includePaths` and `excludePaths`. See [Scope and limits](/crawl/scope). To read only chosen pages, list them with [Map](/map/overview) and send the ones you want to a [batch](/batches/overview).

## 2. Read every page

Wait until the crawl has finished before fetching all its pages. Poll `GET /v1/crawl/{id}` until `status` is `completed`. Then read the pages with `GET /v1/crawl/{id}/results`, up to 100 at a time, and send `cursor` from `data.cursor` until it is missing. Both calls are free, and the pages are kept for 24 hours. See [Read a crawl](/crawl/async).

Each result has the page's `markdown`, its `url`, its `title` and its `depth`. This example shows one page from a three-page crawl. Check `failed` and `errors` before indexing; if there are no pages to index, `results` is empty.

```json
{
  "success": true,
  "data": {
    "results": [
      {
        "markdown": "# Bun Runtime\n\n> Execute JavaScript/TypeScript files, package.json scripts, and …",
        "url": "https://bun.com/docs/runtime",
        "title": "Bun Runtime",
        "depth": 0
      }
    ]
  }
}
```

## 3. Cut each page into chunks

Split at headings, and keep a fenced code block whole, so a shell comment that starts with `#` is not read as a heading. Pack paragraphs into chunks of about 1,200 characters. Every chunk keeps the `url`, the page `title` and the `heading` it sits under. Save this file as `chunk.ts`.

````typescript
export interface Page {
  url: string;
  title: string;
  markdown: string;
}

export interface Chunk {
  id: string;
  url: string;
  title: string;
  heading: string;
  text: string;
}

const MAX_CHARS = 1200;

export function chunkPage({ url, title, markdown }: Page): Chunk[] {
  const chunks: Chunk[] = [];
  let heading = title;
  let blocks: string[] = [];
  let block: string[] = [];
  let inFence = false;

  const endBlock = () => {
    if (block.length > 0) blocks.push(block.join("\n"));
    block = [];
  };
  const endSection = () => {
    endBlock();
    let text = "";
    for (const piece of blocks) {
      if (text !== "" && text.length + piece.length > MAX_CHARS) {
        chunks.push({ id: `${url}#${chunks.length}`, url, title, heading, text });
        text = "";
      }
      text = text === "" ? piece : `${text}\n\n${piece}`;
    }
    if (text !== "") chunks.push({ id: `${url}#${chunks.length}`, url, title, heading, text });
    blocks = [];
  };

  for (const line of markdown.split("\n")) {
    if (line.startsWith("```")) inFence = !inFence;
    if (!inFence && /^#{1,3} /.test(line)) {
      endSection();
      heading = line.replace(/^#+ /, "");
    } else if (!inFence && line.trim() === "") {
      endBlock();
    } else {
      block.push(line);
    }
  }
  endSection();
  return chunks;
}
````

Pass every row in `data.results` to `chunkPage`. Keep each chunk's `id`, `url`, `title`, `heading` and `text`. Repeat for each page of results, using the same `limit` with the next `cursor`. The three example pages produced 61 chunks. The longest was 1,483 characters because the chunker keeps code blocks whole.

## 4. Index with the source

Keep the source alongside every embedding so a retrieved passage can be cited. Embed `text` with your model and store the whole chunk next to the vector: `id`, `url`, `title`, `heading` and `text`. The `id` is the page URL and the chunk number. When you crawl a page again, delete the chunks with that `url` first, then add the new ones, so no old chunk stays behind.

When your retrieval returns a chunk, show `title`, `heading` and a link to `url`. Put the `url` in the prompt too, and tell the model to cite it.

## 5. Keep it fresh

Crawl again when you want to rebuild the whole index. To re-read only what changed, create a [monitor](/monitors/targets#crawl-targets) with a `crawl` target on the same section. It sends a `monitor.page` event for each page that changed or appeared. Read those pages again with [Scrape](/scrape/overview) and replace their chunks.

## What to check

Check the crawl and the chunks before sending them to the index.

- The crawl's `completed` equals its `total`, and `errors` is empty. Pages that failed are listed in `GET /v1/crawl/{id}/errors`.
- Every chunk has a `url` under your start page.
- The chunk count per page is plausible. A page with 1 chunk and 20,000 characters means the headings were not split.
- Pick three chunks, open their `url` and find the text. If you cannot, fix the chunker before you embed.
- Ask three questions you know the answer to. The right page should come back in the top results.

## What it costs

Crawl costs $1 per 1,000 pages, which is $0.001 a page. A 100-page section costs $0.10, and a 1,000-page section costs $1. Reading the results costs nothing, and neither does a page that fails. A monitor on the same section costs the same per page, on every check. See [Pricing](/account/pricing).
