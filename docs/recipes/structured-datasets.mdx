Turn a list of URLs into CSV rows with the same columns. Use a batch to read the pages in the background, then turn the fields it finds into rows.

You need an API key in `STOPHY_API_KEY`. See the [Quickstart](/quickstart). Each page costs $0.004 with a schema. The run on this page read 3 pages and cost $0.012.

## 1. Describe the row

Define the columns you want before you submit the batch. Use strings for `title`, `author` and `publishedOn`, and an array of strings for `topics`. Add `"required": ["title", "publishedOn"]` to request those two fields on every page. Still check for missing values. Use `description` on `publishedOn` to ask for `YYYY-MM-DD`.

See [JSON](/scrape/json) for what a schema can hold.

## 2. Submit the batch

Submit the page list once when every page should use the same schema. It answers at once with an `id`. Send `formats` with the `json` format and your `schema`.

## 3. Read the answers

Read `url` while `status` is `scraping`. Stop polling when it reaches a final state. This batch took 6 seconds. Each page in `data` holds its object in `json`, and its address in `metadata.url`. This response shows one row with no `topics` field.

```json
{
  "success": true,
  "status": "completed",
  "costUsd": 0.012,
  "data": [
    {
      "json": {
        "title": "Behind The Scenes of Bun Install",
        "author": "example_user",
        "publishedOn": "2025-09-10"
      },
      "metadata": {
        "url": "https://bun.com/blog/behind-the-scenes-of-bun-install"
      }
    }
  ]
}
```

The page in this example has no `topics`. The field was optional, and the page lists none. Your code has to expect that. `creditsUsed` is the charge in steps of $0.002, so 6 is $0.012.

An answer holds up to 100 pages or 2 MB, so a long batch comes back in parts. Follow `next` until it is missing. `errors` lists the pages that could not be read, and a failed page costs nothing. See [Batch results](/batches/results).

## 4. Write the rows

Turn each page with a `json` object into a flat row. Get the URL from `metadata.url`. Fill a missing field with an empty string, or skip the row if your app needs that field. Join `topics` with `; ` before you pass the rows to the CSV writer.

```typescript
export function toCsv(rows: Record<string, string>[]): string {
  const first = rows[0];
  if (first === undefined) return "";
  const columns = Object.keys(first);
  const cell = (value: string) => `"${value.replaceAll('"', '""')}"`;
  const lines = rows.map((row) => columns.map((name) => cell(row[name] ?? "")).join(","));
  return [columns.join(","), ...lines].join("\n");
}
```

The sample batch produced three rows. The article without `topics` had an empty cell in that column. If none of the pages returned a row, `toCsv` returns an empty string.

## What to check

Compare the batch counts with the rows before publishing the CSV.

- `completed` plus `failed` equals `total`, after a completed run. Compare your row count with the number of pages that returned usable `json`.
- Open three pages and compare each cell with the page. The model fills a field from the page text, so a field the page does not state can come back wrong or empty.
- Check for missing values even in `required` fields. Count the empty cells in optional columns to decide whether to keep those columns.
- Dates are in one format. If not, tighten the `description` and read a few pages again.
- Store `url` and the time you read it with each row, so you can tell how old a row is.
