You have a list of pages and want a table: one row per page, the same columns every time. You describe the columns as a JSON schema, a batch reads every page in the background, and you flatten the answers into rows.

You need an API key in `STOPHY_API_KEY`. See the [Quickstart](/quickstart). Each page costs $0.004 with a schema. The run on this page read 3 pages and cost $0.012.

## 1. Describe the row

The schema is one row. Mark the fields every page has as `required`, and leave the others optional, so a page that lacks one still returns a row. `description` tells the model the format you want.

```json
{
  "type": "object",
  "properties": {
    "title": { "type": "string" },
    "author": { "type": "string" },
    "publishedOn": { "type": "string", "description": "The publication date as YYYY-MM-DD." },
    "topics": { "type": "array", "items": { "type": "string" } }
  },
  "required": ["title", "publishedOn"]
}
```

See [JSON](/scrape/json) for what a schema can hold.

## 2. Submit the batch

A batch reads a list of URLs in the background. It answers at once with an `id`. Send `formats` with the `json` format and your `schema`.

An answer holds up to 100 pages or 2 MB, so a long batch comes back in parts. Follow `next` until it is missing. `errors` lists the pages that could not be read, and a failed page costs nothing. See [Read a crawl](/crawl/async), which a batch works like.

## 4. Write the rows

This function waits for `completed`, follows `next`, turns each `json` into a flat row with its `url`, fills a missing field with an empty string, and writes a CSV.

```typescript
interface Post {
  title: string;
  author?: string;
  publishedOn: string;
  topics?: string[];
}

interface BatchAnswer {
  status: string;
  data: { json?: Post; metadata: { url: string } }[];
  next?: string;
}

const headers = { Authorization: `Bearer ${process.env.STOPHY_API_KEY}` };

async function get(url: string): Promise<BatchAnswer> {
  return (await fetch(url, { headers })).json();
}

export async function readRows(batchUrl: string): Promise<Record<string, string>[]> {
  let answer = await get(batchUrl);
  while (answer.status === "queued" || answer.status === "scraping") {
    await new Promise((resolve) => setTimeout(resolve, 2000));
    answer = await get(batchUrl);
  }
  const rows: Record<string, string>[] = [];
  for (;;) {
    for (const page of answer.data) {
      if (page.json === undefined) continue;
      rows.push({
        url: page.metadata.url,
        title: page.json.title,
        author: page.json.author ?? "",
        publishedOn: page.json.publishedOn,
        topics: (page.json.topics ?? []).join("; "),
      });
    }
    if (answer.next === undefined) return rows;
    answer = await get(answer.next);
  }
}

export function toCsv(rows: Record<string, string>[]): string {
  const first = rows[0];
  if (first === undefined) return "";
  const columns = Object.keys(first);
  const cell = (value: string) => `"${value.replaceAll('"', '""')}"`;
  const lines = rows.map((row) => columns.map((name) => cell(row[name] ?? "")).join(","));
  return [columns.join(","), ...lines].join("\n");
}
```

## What to check

- `completed` plus `failed` equals `total`, and your row count equals `completed`.
- Open three pages and compare each cell with the page. The model fills a field from the page text, so a field the page does not state can come back wrong or empty.
- `required` fields are never empty. Count the empty cells of each optional column, and decide if the column is worth keeping.
- Dates are in one format. If not, tighten the `description` and read a few pages again.
- Store `url` and the time you read it with each row, so you can tell how old a row is.
