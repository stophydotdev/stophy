---
title: "Zero data retention"
description: "Use zero data retention, and see what is kept temporarily and which features are refused."
---

Set `zeroDataRetention: true` on a supported call to skip shared and saved copies of its content. Billing and operational metadata remain. Jobs and live browser sessions need temporary state.

```bash
curl -X POST https://api.stophy.dev/v1/scrape \
  -H "Authorization: Bearer $STOPHY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://example.com", "formats": ["markdown"], "zeroDataRetention": true}'
```

## Where to send it

| Endpoint | Field |
| - | - |
| [Scrape](/scrape/overview), [batches](/batches/overview) | `zeroDataRetention` |
| [Search](/search/overview) | `scrapeOptions.zeroDataRetention` |
| [Extract](/extract/overview), [crawl](/crawl/overview) | `zeroDataRetention` or `scrapeOptions.zeroDataRetention` |
| [Parse](/parse/overview), [agent](/agent/overview), [browser sessions](/browser/overview) | `zeroDataRetention` |

## What changes

* Shared content copies and model answer caches are not read or written. ZDR requests do not go to OpenAI. Other providers may process the request.
* A ZDR scrape result is not saved for later retrieval. Read it from the response.
* ZDR crawl, batch, extract, and agent jobs use temporary Redis state for polling. Their private job or result records have a one-hour lifetime. Live browser sessions also need temporary state.
* Billing and operational metadata remain. Logs and third-party systems may retain information; ZDR is not a promise of physical deletion from every backup or provider.
* Your app is responsible for what it stores and logs from the answers.

## Refusals

ZDR requests refuse features that need retained content:

* Webhooks on crawl, batch, extract, and other jobs. Poll for results instead.
* Browser tasks. Use a browser session instead.
* Screenshots and screenshot or PDF actions, change tracking, profiles, and `onlyCleanContent` on scrape paths.
* `threadId` on agent; profiles and recording on browser sessions; and monitors.

See [retention](/trust/retention) for the limits of deletion evidence.
