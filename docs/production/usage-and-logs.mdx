Use logs to find a billed call and see what it cost. The log records the endpoint, time and key, not the request or response body. These calls are free and need an API key. For your balance and spending over time, see [Usage](/account/usage).

## List your recent calls

Use the log list to compare recent charges for a key or endpoint. `GET /v1/logs` lists your billed calls, newest first, 50 to a page.

<CodeGroup>
```bash cURL
curl "https://api.stophy.dev/v1/logs?days=1&endpoint=scrape" \
  -H "Authorization: Bearer $STOPHY_API_KEY"
```
```typescript TypeScript
import { Stophy } from "stophy";

const stophy = new Stophy();

const { logs, total } = await stophy.logs({ days: 1, endpoint: "scrape" });
console.log(total, logs[0]);
```
```python Python
from stophy import Stophy

stophy = Stophy()

body = stophy.logs(days=1, endpoint="scrape")
print(body["total"], body["logs"][0])
```
</CodeGroup>

Read the rows in `logs`. This example shows one row with an example key ID and name.

```json
{
  "logs": [
    {
      "requestId": "f9a3f2e7-124d-4623-9bba-6408b5eebfa3",
      "createdAt": "2026-11-17T17:48:15.571Z",
      "endpoint": "scrape",
      "costUsd": 0.003,
      "apiKeyId": "key_example",
      "apiKeyName": "My app"
    }
  ],
  "page": 0,
  "pageSize": 50,
  "total": 126,
  "totalPages": 3
}
```

Rows include the log `id`, HTTP method and status, and `response`. The answer also lists the endpoint IDs you can filter by in `endpoints`. If nothing matches, `logs` is empty.

| Parameter | Default | What it does |
| - | - | - |
| `days` | 7 | How far back to look, 1 to 90 |
| `page` | 0 | The page number, from 0 |
| `apiKeyId` | All | Only calls made with this key |
| `endpoint` | All | Only calls to this endpoint id, such as `scrape` or `crawl` |

Only calls that were billed are logged. A free call, an error and an empty result have no entry. A billed call with [zero data retention](/production/zero-data-retention) still appears in the logs. The log contains billing fields, not the content you sent or received. Logs are kept for 90 days.

## Read one call

Use `GET /v1/logs/{id}` to check the charge for a single request. It takes the `requestId` of any answer. It looks back `days` days, 7 by default and up to 90.

Read `data.costUsd` for the billed amount. The row also gives the request ID, endpoint, creation time and API key ID and name. `charges` is how many times the call was charged. A crawl or a batch is charged once for each page, so one request id can have many charges. A request id that was not billed in that time answers `404` with code `notFound`.

## List your billed calls by cursor

Use `GET /v1/team/activity` if you prefer a cursor. It returns the same calls in a shorter shape, with a cursor instead of page numbers. It is free. Each `data` row has `id`, `endpoint`, `api_version` and `created_at`.

| Parameter | Default | What it does |
| - | - | - |
| `endpoint` | All | Only calls to this endpoint, such as `scrape` |
| `limit` | 50 | Calls a page, 1 to 100 |
| `cursor` | None | The `cursor` the last page returned. Stop when `has_more` is `false`. |

## See your running jobs

Use `GET /v1/team/queue-status` to see whether there is room to start more jobs. It counts your crawl, batch and agent jobs that are running or waiting.

Read `activeJobsInQueue` for running jobs, `waitingJobsInQueue` for waiting jobs and `jobsInQueue` for the total. `maxConcurrency` is how many jobs can run at once on your tier. `mostRecentSuccess` is when your last billed call finished. See [Rate limits](/production/rate-limits).

## See what extract and agent used

Use token usage to compare Extract and Agent for the current month. `GET /v1/team/token-usage` uses older field names ending in `Tokens`. The values count billed amounts in steps of $0.002, not model tokens.

Read `tokensUsed` for the total, `byEndpoint` for the split, and `usedSince` for the start of the period. `remainingTokens` is your balance in whole steps of $0.002, and the plan and period fields are `null` because there are no plans. `GET /v1/team/token-usage/historical` returns one row for each month with `tokensUsed`, and `byApiKey=true` splits each month by key.

## Match a request to its log

Save the `requestId` of every call you care about. It is in the `X-Request-ID` header of every answer and in the body of most, and it is the id `GET /v1/logs/{id}` and [feedback](/production/agent-feedback) take. See [Troubleshooting](/production/troubleshooting).
