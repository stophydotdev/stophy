Every [agent](/agent/overview) run has an `id`. Use it to read the answer, follow the steps, stop the run, or ask a follow-up. All of these calls are free, and a run is kept for 24 hours.

## Read a run

Get an API key in the [Quickstart](/quickstart). `GET /v1/agent/{id}` returns the state of a run.

<CodeGroup>
```bash cURL
curl https://api.stophy.dev/v1/agent/job_1U1n0vXaDokDUHZFMGj1rA \
  -H "Authorization: Bearer $STOPHY_API_KEY"
```
```typescript TypeScript
const response = await fetch("https://api.stophy.dev/v1/agent/job_1U1n0vXaDokDUHZFMGj1rA", {
  headers: { Authorization: `Bearer ${process.env.STOPHY_API_KEY}` },
});
const run = await response.json();
console.log(run.status, run.data, run.sources);
```
```python Python
import os

import requests

response = requests.get(
    "https://api.stophy.dev/v1/agent/job_1U1n0vXaDokDUHZFMGj1rA",
    headers={"Authorization": f"Bearer {os.environ['STOPHY_API_KEY']}"},
)
run = response.json()
print(run["status"], run["data"], run["sources"])
```
</CodeGroup>

The response is in [Agent](/agent/overview#read-the-response). These are its fields.

| Field | What it holds |
| - | - |
| `status` | `processing` while the run is queued or working, `completed` when it ended with an answer, `failed` when it ended without one or was stopped. |
| `queuePosition` | Where the run waits, while it is queued. |
| `data` | The fields the agent found. A field it did not find is left out. |
| `confidence` | For each field, a number from 0 to 1. |
| `sources` | For each field, the `url` and the exact `quote` it came from. Left out with `includeSources: false`. |
| `stoppedBy` | Why the run ended: `done`, `rounds` or `maxCredits`. |
| `stopReason`, `partial`, `partialSchemaValid` | With `credit_limit_reached`: what the run found before the cap, and whether it fills your schema. |
| `message` | The reply to a `chat` follow-up. |
| `error` | Why a run failed. |
| `steps` | What the run did: `n`, `action`, `detail` and `costUsd` for each step. |
| `skipped` | Pages the run could not read, each with an `error` and a `url`. |
| `model`, `mode`, `effort` | What the run used. |
| `threadId`, `threadTurn` | The thread of the run and the turn of the run in it. |
| `costUsd` | What the run has cost so far. |
| `createdAt`, `completedAt`, `expiresAt` | When the run started, when it ended and when it is deleted. |

## List runs

`GET /v1/agent` lists your runs from the last 24 hours, newest first, 20 to a page. Each row has the `id`, `createdAt`, `status`, `targetHint` and the `options` the run started with.

```bash
curl https://api.stophy.dev/v1/agent \
  -H "Authorization: Bearer $STOPHY_API_KEY"
```

This real response is cut to the first run of three.

```json
  "agents": [
```

When more runs follow, `next` holds the address of the next page. Or send `before`, a time in unix milliseconds, and read runs made before it. `limit` is 1 to 20.

## Stop a run

`DELETE /v1/agent/{id}` stops a run that is still working and keeps what it has read. What it spent is charged. The answer has `status` of `cancelled`.

```bash
curl -X DELETE https://api.stophy.dev/v1/agent/job_1U1n0vXaDokDUHZFMGj1rA \
  -H "Authorization: Bearer $STOPHY_API_KEY"
```

A run that already ended cannot be stopped. This real answer came from a run that had finished, with HTTP status `409`.

```json
{
  "retryable": false,
  "requestId": "35660548-bae0-4170-972e-bbf2cbd30c47",
  "success": false,
  "error": "This agent run already finished, so there is nothing to cancel. Read its pages with GET /v1/agent/job_1U1n0vXaDokDUHZFMGj1rA.",
  "code": "jobFinished"
}
```

## Read the trace

`GET /v1/agent/{id}/trace` returns every step of a run, in order, as events: when the run started, each step with what it cost, a snapshot of the answer after each round, the final answer, and when the run finished. A page the run could not read is an `error.occurred` event.

```bash
curl https://api.stophy.dev/v1/agent/job_1U1n0vXaDokDUHZFMGj1rA/trace \
  -H "Authorization: Bearer $STOPHY_API_KEY"
```

## Read a snapshot

A run takes up to three rounds, and the trace has a snapshot after each: its `snapshotId` is `round-1`, `round-2` and so on. `GET /v1/agent/{id}/snapshots/{snapshotId}` returns the answer the run had at that point. Use it to see how the answer grew, or to keep an earlier round.

```bash
curl https://api.stophy.dev/v1/agent/job_1U1n0vXaDokDUHZFMGj1rA/snapshots/round-1 \
  -H "Authorization: Bearer $STOPHY_API_KEY"
```

```json
{
  "success": true,
  "id": "job_1U1n0vXaDokDUHZFMGj1rA",
  "snapshotId": "round-1",
  "snapshot": "{\"data\":{\"module\":\"bun:sqlite\"},\"confidence\":{\"module\":0.9388}}",
  "snapshotData": {
    "data": { "module": "bun:sqlite" },
    "confidence": { "module": 0.9388 }
  },
  "costUsd": 0,
  "requestId": "73863efc-61f7-4425-bc68-b0ecea15d640"
}
```

`snapshot` is the answer as a JSON string, and `snapshotData` is the same answer as an object.

## Ask a follow-up

Send `threadId` with a new `prompt` to ask in the same thread. The run sees your earlier question and answer, and `urls`, `schema`, `effort`, `mode`, `location` and `safe` carry over unless you send new ones. With `"mode": "chat"`, a follow-up that needs no new data gets a short reply in `message`, for $3 per 1,000 pages, and a follow-up that needs more reads the pages again.

<CodeGroup>
```bash cURL
curl -X POST https://api.stophy.dev/v1/agent \
  -H "Authorization: Bearer $STOPHY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "prompt": "Which of those modes does a plain transaction use?",
    "threadId": "job_1U1n0vXaDokDUHZFMGj1rA",
    "mode": "chat",
    "maxCredits": 25
  }'
```
```typescript TypeScript
const response = await fetch("https://api.stophy.dev/v1/agent", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.STOPHY_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    prompt: "Which of those modes does a plain transaction use?",
    threadId: "job_1U1n0vXaDokDUHZFMGj1rA",
    mode: "chat",
    maxCredits: 25,
  }),
});
const followUp = await response.json();
console.log(followUp.id, followUp.threadTurn);
```
```python Python
import os

import requests

response = requests.post(
    "https://api.stophy.dev/v1/agent",
    headers={"Authorization": f"Bearer {os.environ['STOPHY_API_KEY']}"},
    json={
        "prompt": "Which of those modes does a plain transaction use?",
        "threadId": "job_1U1n0vXaDokDUHZFMGj1rA",
        "mode": "chat",
        "maxCredits": 25,
    },
)
follow_up = response.json()
print(follow_up["id"], follow_up["threadTurn"])
```
</CodeGroup>

The follow-up is a new run with its own `id`. It keeps the `threadId` and has `threadTurn` of 2.

```json
{
  "success": true,
  "id": "job_u8CXI2icHrwCUpX-DP_5Cg",
  "url": "https://api.stophy.dev/v1/agent/job_u8CXI2icHrwCUpX-DP_5Cg",
  "threadId": "job_1U1n0vXaDokDUHZFMGj1rA",
  "threadTurn": 2,
  "costUsd": 0,
  "requestId": "7cf70786-b777-49ac-809e-2c3ab4f8b0d1"
}
```

In this run the first step was `chat`, which tried to answer from the earlier answer at no cost. The earlier answer did not hold the modes, so the run read the page again and charged $0.004.

## Read a thread

`GET /v1/agent/threads/{threadId}` returns every turn of a thread, oldest first. Add `includeData=true` to get the `data` of each finished run.

```bash
curl "https://api.stophy.dev/v1/agent/threads/job_1U1n0vXaDokDUHZFMGj1rA?includeData=true" \
  -H "Authorization: Bearer $STOPHY_API_KEY"
```

This real response is cut to the second turn.


The `status` of a thread is `running` while a turn works and `idle` otherwise. A run's `status` is `processing`, `succeeded`, `failed`, `cancelled` or `credit_limit_reached`.

## Options

| Field | Where | Effect |
| - | - | - |
| `before` | `GET /v1/agent` | Only runs made before this time, in unix milliseconds. |
| `limit` | `GET /v1/agent` | How many runs, 1 to 20. The default is 20. |
| `includeData` | thread | `true` adds the `data` of each finished run. |
| `threadId` | `POST /v1/agent` | Ask a follow-up in this thread. |
| `mode` | `POST /v1/agent` | `chat` replies from the earlier answer when it can. |
| `maxTextLength` | every read | A query parameter. Cuts every text value in the response to this many characters. |

## Limits and errors

- Runs, threads, traces and snapshots are kept for 24 hours. An unknown run returns `404 notFound`. An unknown thread returns `404 notFound` with `No agent thread with that id. Threads are kept for 24 hours.` An unknown snapshot returns `404 notFound` with `No snapshot with that id for this run.`
- `DELETE` on a run that already ended returns `409 jobFinished`.
- `zeroDataRetention` cannot be sent with `threadId`: a thread keeps what it has said.
- `strictConstrainToURLs` with no `urls`, and no thread that has them, returns `400 invalidRequest`.
- You can read only your own runs.
