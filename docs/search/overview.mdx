---
title: "Search"
description: "Find web pages, news, images, papers and videos from a query in one request, and optionally read the page text of each result. Works without an API key."
---

Use Search when you have a query instead of a URL. You get one ranked list per source, and web results by default.

<CodeGroup>
```bash cURL
curl -X POST https://api.stophy.dev/v1/search \
  -H "Authorization: Bearer $STOPHY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "bun runtime",
    "sources": ["web", "news"],
    "limit": 3
  }'
```
```typescript TypeScript
import { Stophy } from "stophy";

const stophy = new Stophy();

const { data } = await stophy.search({
  query: "bun runtime",
  sources: ["web", "news"],
  limit: 3,
});
for (const result of data?.web ?? []) {
  console.log(result.position, result.title, result.url);
}
```
```python Python
from stophy import Stophy

stophy = Stophy()

data = stophy.search(
    query="bun runtime",
    sources=["web", "news"],
    limit=3,
)["data"]
for result in data["web"]:
    print(result["position"], result["title"], result["url"])
```
</CodeGroup>

Search works without a key, within the keyless limits in [Rate limits](/production/rate-limits). Reading result pages needs a key. Get one in the [Quickstart](/quickstart).

## Response

`data` holds one list per source, each row ranked by `position`.

```json
{
  "success": true,
  "data": {
    "news": [{ "url": "https://bun.com/blog/bun-v1.4.4", "position": 2 }],
    "web": [{ "url": "https://github.com/oven-sh/bun", "position": 1, "category": "github" }]
  }
}
```

A web row has `url`, `title` and `description`, plus `date` when known and `category` (`github`, `research` or `pdf`) when the page is one of those. A news row has `snippet` instead of `description`, and may have `imageUrl`.

If a source fails or returns fewer rows than you asked for, the call still succeeds and `warning` names the source. If every source fails, the call fails. The `x-cost-usd` header is what the call cost. See [Pricing](/account/pricing).

## Fields

| Field | Default | Effect |
| - | - | - |
| `query` | required | 1 to 500 characters. Web results take `"exact phrase"`, `-word`, `site:`, `-site:`, `filetype:`, `inurl:`, `allinurl:`, `intitle:` and `allintitle:`. Images take `imagesize:WIDTHxHEIGHT` and `larger:WIDTHxHEIGHT`. |
| `sources`, `categories` | `["web"]` | What to return. See [Options](/search/options#sources). |
| `includeDomains`, `excludeDomains`, `tbs`, `location`, `country`, `lang`, `safe` | none | Narrow by site, time, place or language. See [Options](/search/options#filters). |
| `scrapeOptions`, `scrapeLimit`, `highlights` | none | Read each result page, or only matching passages. See [Options](/search/options#page-content). |
| `limit` | 10, or 5 with `scrapeOptions.formats` | Most results per source, 1 to 100. News returns at most 50. |
| `maxAge` | 1 hour, 15 minutes for news | Accept a stored answer up to this many milliseconds old, at most 30 days. `0` searches live. A stored answer has `cachedAt`. |
| `timeout` | 3,000 ms, 60,000 ms with `scrapeOptions.formats` | Milliseconds to wait for sources, 1,000 to 120,000. A source that has not answered is left out with a `warning`. |
| `ignoreInvalidURLs` | `false` | Leave out results whose address is not a readable page. |

Two more endpoints search one kind of content: [Papers](/search/papers) and [Developer search](/search/developer). The full field list is in the [API reference](/api-reference/endpoint/search).
