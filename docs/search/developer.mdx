`POST /v1/search/developer` finds READMEs, issues, pull requests, releases, API operations and docs for a query, each with the passage that matches. It needs an API key.

## Search issues of a repo

Get an API key in the [Quickstart](/quickstart). This request looks for issues and pull requests about SQLite transactions in one repo.

<CodeGroup>
```bash cURL
curl -X POST https://api.stophy.dev/v1/search/developer \
  -H "Authorization: Bearer $STOPHY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "sqlite transactions",
    "k": 3,
    "types": ["issue", "pull_request"],
    "repos": ["oven-sh/bun"],
    "language": "Rust"
  }'
```
```typescript TypeScript
const response = await fetch("https://api.stophy.dev/v1/search/developer", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.STOPHY_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    query: "sqlite transactions",
    k: 3,
    types: ["issue", "pull_request"],
    repos: ["oven-sh/bun"],
    language: "Rust",
  }),
});
const { results } = await response.json();
for (const result of results) {
  console.log(result.type, result.state, result.title, result.url);
}
```
```python Python
import os

import requests

response = requests.post(
    "https://api.stophy.dev/v1/search/developer",
    headers={"Authorization": f"Bearer {os.environ['STOPHY_API_KEY']}"},

    },

for result in response.json()["results"]:
    print(result["type"], result["state"], result["title"], result["url"])
```

Each result has an `id`, the `url` and `title` of the item, its `type`, and the `repo`, `stars`, `language`, `date` and `state` (such as `open` or `closed`) when it has them, or `null`. `passages` holds the text that matched, and each passage names the `citation_url` to cite. `repos` has one entry for each repo you sent, and `indexed` says whether Stophy holds items of that repo.

## Search one repo without passages

Send `passages` as `false` when you only need the items. This request searches the READMEs, issues, pull requests and releases of one repo.

```bash
curl -X POST https://api.stophy.dev/v1/search/developer \
  -H "Authorization: Bearer $STOPHY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "memory leak",
    "k": 2,
    "types": ["readme", "issue", "pull_request", "release"],
    "repos": ["oven-sh/bun"],
    "passages": false
  }'
```

## Send a GET request

`GET /v1/search/developer` takes the same fields as query parameters, with a list as comma-separated values, such as `?query=memory+leak&types=issue,pull_request&repos=oven-sh/bun`.

## Options

| Field | Type | Default | Effect |
| - | - | - | - |
| `query` | `string` | none | What to search for. Required. |
| `k` | `number` | 10 | How many results, 1 to 100. |
| `types` | `array of string` | all types | Keep only these types: `readme`, `issue`, `pull_request`, `release`, `operation` or `doc`. |
| `repos` | `array of string` | none | Search only these repos, up to 5, as `owner/name`. Each one gets an entry in `repos`. |
| `language` | `string` | none | Keep only items of repos written in this language, such as `Rust`. |
| `min_stars` | `number` | none | Keep only items of repos with at least this many stars. |
| `max_stars` | `number` | none | Keep only items of repos with at most this many stars. |
| `passages` | `boolean` | `true` | Send `false` to get results without their passages. `passages` is then an empty list. |

## Limits and errors

- Without an API key, the call returns `401 apiKeyRequired`.
- `min_stars` above `max_stars` returns `400 invalidRequest` with `min_stars: must not be greater than max_stars.`
- `operation` and `doc` results have no stars, so they are left out when you send `min_stars` or `max_stars`.
- A `repos` entry that is not `owner/name`, or more than 5 repos, returns `400 invalidRequest`. A repo Stophy holds nothing of comes back with `indexed: false`.
- `partial` is `false` on every answer.
