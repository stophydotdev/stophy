Use Developer search for a passage you can cite from a README, issue, pull request, release, API operation or docs page. Needs an API key.

```bash cURL
curl -X POST https://api.stophy.dev/v1/search/developer \
  -H "Authorization: Bearer $STOPHY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "sqlite transactions",
    "k": 3,
    "types": ["issue", "pull_request"],
    "repos": ["oven-sh/bun"]
  }'
```

`GET /v1/search/developer` takes the same fields as query parameters, with lists as comma-separated values: `?query=memory+leak&types=issue,pull_request&repos=oven-sh/bun`.

```json
{
  "results": [
    {
      "passages": [
        {
          "text": "oven-sh/bun issue #26044 · open · labels: docs\n\n…",
          "citation_url": "https://github.com/oven-sh/bun/issues/26044"
        }
      ],
      "type": "issue"
    }
  ],
  "costUsd": 0.001
}
```

Results are best first. Cite `passages[].citation_url`. Each result also has `id`, `url`, `title`, `type`, and `repo`, `stars`, `language`, `date` and `state` (such as `open`), each `null` when unknown. `repos` in the response has one entry per repo you sent, and `indexed` says whether we have items for it.

| Field | Default | Effect |
| - | - | - |
| `query` | required | What to search for. |
| `k` | 10 | How many results, 1 to 100. |
| `types` | all | `readme`, `issue`, `pull_request`, `release`, `operation` or `doc`. |
| `repos` | none | Search only these repos as `owner/name`, up to 5. |
| `language` | none | Keep repos written in this language, such as `Rust`. |
| `min_stars`, `max_stars` | none | Keep repos with at least or at most this many stars. `min_stars` above `max_stars` returns `400`. `operation` and `doc` results have no stars, so these filters drop them. |
| `passages` | `true` | `false` returns links and titles with an empty `passages` list. |
