A crawl runs in the background. `POST /v1/crawl` answers at once with an `id`, and these calls let you follow it: read its status and finished pages, read its errors, cancel it, and list your crawls. All of them are free and need the same API key. A crawl and its pages are kept for 24 hours.

## Poll a crawl and read every page

Poll `GET /v1/crawl/{id}` until `status` is `completed`, `failed` or `cancelled`. Then follow `next` until the answer has none. This reads every page of a crawl.

<CodeGroup>
```bash cURL
CRAWL_ID="<the id your crawl returned>"
URL="https://api.stophy.dev/v1/crawl/$CRAWL_ID"

while :; do
  BODY=$(curl -s "$URL" -H "Authorization: Bearer $STOPHY_API_KEY")
  case $(echo "$BODY" | jq -r .status) in completed|failed|cancelled) break ;; esac
  sleep 2
done

echo "$BODY" | jq .data
NEXT=$(echo "$BODY" | jq -r '.next // empty')
while [ -n "$NEXT" ]; do
  BODY=$(curl -s "$NEXT" -H "Authorization: Bearer $STOPHY_API_KEY")
  echo "$BODY" | jq .data
  NEXT=$(echo "$BODY" | jq -r '.next // empty')
done
```
```typescript TypeScript
import { Stophy } from "stophy";

const stophy = new Stophy();

const id = "<the id your crawl returned>";
const over = new Set(["completed", "failed", "cancelled"]);

let status = await stophy.crawl.status({ id });
while (!over.has(status.status)) {
  await new Promise((resolve) => setTimeout(resolve, 2000));
  status = await stophy.crawl.status({ id });
}

const pages = [...status.data];
let next = status.next;
while (next !== undefined) {
  const cursor = new URL(next).searchParams.get("cursor") ?? undefined;
  const more = await stophy.crawl.status({ id, cursor });
  pages.push(...more.data);
  next = more.next;
}
```
```python Python
import time
from urllib.parse import parse_qs, urlparse

from stophy import Stophy

stophy = Stophy()

crawl_id = "<the id your crawl returned>"

status = stophy.crawl.status(id=crawl_id)
while status["status"] not in ("completed", "failed", "cancelled"):
    time.sleep(2)
    status = stophy.crawl.status(id=crawl_id)

pages = list(status["data"])
next_url = status.get("next")
while next_url:
    cursor = parse_qs(urlparse(next_url).query)["cursor"][0]
    more = stophy.crawl.status(id=crawl_id, cursor=cursor)
    pages.extend(more["data"])
    next_url = more.get("next")
```
</CodeGroup>

A status answer holds up to 100 finished pages or 2 MB, whichever comes first. That is separate from the `limit` you sent to the crawl, which is how many pages it reads in all. A crawl with `limit` 30 is usually read in one call once it is done, and one with `limit` 250 in three.

`next` appears only when more finished pages are waiting, so it never leads to an empty `data`. It is a full URL on `api.stophy.dev`. Call it with the same API key. The SDK examples send its `cursor` back to `crawl.status`.

For example, with a `limit` of 250 and 100 pages per answer, read the first two `next` links to get all 250 pages. The third answer has no `next`.

## Read the status

Check `status` before reading the pages. While a crawl runs, `status` is `scraping`. If a crawl has found a page but has not finished reading it, `total` can be `1` while `data` is still empty.

```json
{
  "success": true,
  "data": [],
  "status": "scraping",
  "total": 1,
  "completed": 0,
  "failed": 0,
  "costUsd": 0,
  "expiresAt": "2026-11-18T18:03:49.796Z",
  "errors": []
}
```

| Field | What it holds |
| - | - |
| `status` | `scraping`, `completed`, `failed` or `cancelled`. |
| `queuePosition` | Where the crawl waits, when it has not started yet. |
| `total` | The pages found so far. It grows while the crawl runs. |
| `completed`, `failed` | Pages that finished, and pages that could not be read. |
| `data` | The finished pages, in the shape the formats you chose give. See [Page content](/crawl/page-content). |
| `errors` | The failed pages in this answer, each with `url`, `code`, `message`, `retryable` and `at`. |
| `error` | Set only when the whole crawl failed, such as when the start page could not be read. |
| `costUsd` | What the pages read so far cost. |
| `createdAt`, `completedAt`, `duration`, `expiresAt` | Times, and the seconds the crawl ran. The pages are removed at `expiresAt`. |
| `next` | The URL of the next answer, when more finished pages are waiting. |

## Read page by page

If you need the URL and depth of each page, use `GET /v1/crawl/{id}/results`. It returns the finished pages with more detail on each, 20 at a time. Send `limit` up to 100, and send `cursor` from the answer to read the next part. Keep going until `cursor` is missing.

Each result has the `url` the crawl ended on, the `requestedUrl` it followed, the page's `depth` (links from the start page), and its own `costUsd`. For example, with `limit=2` on a three-page crawl, send the first answer's `cursor` with the same `limit` to read the last page. That answer has no `cursor`.

## Read the errors

`GET /v1/crawl/{id}/errors` lists the pages the crawl could not read, and why. If no pages failed, `errors` is empty.

Each item of `errors` has the page's `url`, a stable `code`, a `message`, whether trying again can help (`retryable`) and when it failed (`at`). The list holds up to 1,000 errors, and `isTruncated` says when there were more. A failed page costs nothing. `robotsBlocked` lists up to 1,000 links that a robots.txt the crawl read did not allow. They are skipped, not counted as failures. A link whose robots.txt could not be read is skipped and not listed.

A page that answers with a 404 or 410 status is not an error. It is a finished page with its actual `metadata.statusCode` and a `metadata.error` that says which status the site returned. It costs nothing.

## Cancel a crawl

Use `DELETE /v1/crawl/{id}` when you no longer need a running crawl. The call returns `status: "cancelled"` and keeps the pages it already read. You are charged for those pages and no more.

A crawl that already finished or failed cannot be cancelled. The call returns `409 jobFinished`.

## List your crawls

`GET /v1/crawl` lists your crawls, newest first, 20 at a time. Send `status` to keep one status, `limit` up to 100, and `cursor` from the answer for the next part. A page can hold fewer than `limit`, so keep going until `cursor` is missing.

`GET /v1/crawl/active` lists only the crawls that are waiting or running, each with its `id`, `url`, `status` (`queued` or `scraping`), `createdAt` and the `options` it was started with. When no jobs are waiting or running, `crawls` is empty.

## Get told with a webhook

Send `webhook` when you start the crawl, instead of polling. It is a URL, or an object. We send a JSON `POST` when the crawl starts, for each finished page, and when it ends. For just page and completion events, set `"events": ["page", "completed"]` inside `webhook`. For example, use `"metadata": { "project": "docs" }` to identify the crawl in each delivery.

| `webhook` field | Effect |
| - | - |
| `url` | Where to send the calls. Required. |
| `headers` | Headers sent with every call. |
| `metadata` | An object that comes back in every call. |
| `events` | Which of `started`, `page`, `action`, `completed`, `failed` and `cancelled` to send. All by default. |

Each call is signed in a `Stophy-Signature` header, `t=<unix seconds>,v1=<hex>`, where `v1` is the HMAC-SHA256 of `<t>.<body>` with your webhook secret. A call that gets no `2xx` answer is sent again, up to 3 times. Every call has an `eventId` that stays the same when it is sent again. If your endpoint answers slowly, a `page` event can carry only the page's `url`. Read that page with the status call. See [Webhooks](/webhooks).

## Options

Set these fields in `POST /v1/crawl` when you want notifications, a limit on how fast we read pages, or shorter retention.

| Field | Type | Default | Effect |
| - | - | - | - |
| `webhook` | `string` or `object` | none | Be told as the crawl runs. See above. |
| `delay` | `number` | none | Seconds to wait between pages, up to 60. With `delay` the crawl reads one page at a time. |
| `maxConcurrency` | `number` | none | The most pages read at once, 1 to 100. A crawl reads at most 4 pages at once, so a larger number gives the same speed. |
| `zeroDataRetention` | `boolean` | `false` | Keep nothing from the crawl: no stored copy is read or made, results are held for one hour at most, and nothing is logged. Adds $2 per 1,000 pages. |

## Batches work the same way

A [batch scrape](/batches/overview) is read like a crawl, at `https://api.stophy.dev/v1/batch/scrape/<id>`, with `/results` and `/errors` under it. Its pages are kept for 24 hours as well.

## Limits and errors

Use the status and error code to tell a failed crawl from a missing job or an invalid request.

- A status answer holds up to 100 pages or 2 MB. `/results` holds up to 100 pages, 20 by default.
- An `id` that does not exist, belongs to another account, or has expired returns `404 notFound`.
- A `cursor` is only good for the crawl and the `limit` it came from. Send it unchanged.
- A crawl that has failed shows `status` `failed` and the reason in `error`.
- Without an API key, every call returns `401 apiKeyRequired`.

## Price

Free. Reading, listing, cancelling and reading errors cost nothing. The pages a crawl reads are charged when they finish, at the price in [Crawl](/crawl/overview#price).
