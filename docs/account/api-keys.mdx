title: "API keys"
description: "Create an API key, let an agent sign up for one, check its expiry, revoke it, and see which calls work without a key at all."
---

Send your key on every call as `Authorization: Bearer $STOPHY_API_KEY`. Every key on an account spends from one balance. Keep the key in a server secret store, out of committed code and browser code.

## Create a key

* Sign up at [stophy.dev/signup](https://stophy.dev/signup) with GitHub or Google, then create a key. A new account has a starting balance, see [Pricing](/account/pricing).
* `stophy login` in the [CLI](/install-cli) makes a key for that computer. Logging in again replaces it.
* Browser sign-in over [MCP](/install-mcp) needs no key.

## Sign up from an agent

The agent asks for a key and you approve it. The [Agent quickstart](/agent-quickstart) has the full steps. Over MCP, `stophy_signup` does the same.

1. The agent calls `POST /v1/signup`. It needs no key and is free. The answer holds a `claimUrl`, a secret `code` and `expiresAt`.
2. You open `claimUrl`, sign in with GitHub or Google and approve.
3. The agent polls `POST /v1/signup/poll` with the `code` every few seconds. It gets `202` with `status: "waiting"`, then `200` with the `apiKey`, once.

The link and code last 24 hours. An unknown, expired or collected code answers `404` `notFound`: sign up again. See [Rate limits](/production/rate-limits) for the signup cap.

## Check expiry

`GET /v1/limits` returns `data.keyExpiresAt`, `null` when the key does not expire, as for a key an agent collected. After that time the key answers `401` `unauthorized`, the same as a wrong or revoked key. The error carries `signupUrl` and `signup` for a new key.

## Revoke a key

`DELETE /v1/key` revokes the key you call it with, at once. It is free and needs a key, not a signed-in session. `stophy logout` does the same for the CLI key.

To replace a key, create the new one, update your app, then revoke the old one. Filter [`GET /v1/logs`](/account/usage#list-calls) or `GET /v1/usage/history` by `apiKeyId` to see one key's calls.

## Calls without a key

Search, scrape, map and parse work without a key, within the keyless limits in [Rate limits](/production/rate-limits#without-a-key). A parser works when `keyless` is `true` in `GET /v1/parsers`. `GET /v1/keyless/eligibility` needs no key and returns `eligible`, `remainingToday` and `remainingThisMinute`.

Everything else answers `401` `apiKeyRequired`, and so does a keyless call that uses one of these. The answer carries `signupUrl` for a person and `signup` for an agent.

| Needs a key | On |
| - | - |
| `page` other than 1, `cursor` | Every endpoint that pages |
| `actions`, `profile`, `waitFor`, `checkPromptInjection`, `onlyCleanContent`, `redactPII` | Scrape |
| `json` with a `schema` or a `prompt`, `audio`, `video` | Scrape |
| A parser not marked `keyless`, and any parser option such as `cursor` | Scrape |
| `scrapeOptions` | Search |
| `includeSubdomains: true` | Map |
| A file over the keyless size limit | Parse |
| Every call | Crawl, batches, extract, agent, browsers, monitors, webhooks |

Over the keyless limit, a call answers `429` `freeLimit` with `signupUrl` and `retryAfterSeconds`.
