Use a batch when you already have several URLs to read. Use [Crawl](/crawl/overview) if you want us to find the URLs for you. You send the list once, get an `id` at once, and read the pages when they finish.

## Make a request

Get an API key in the [Quickstart](/quickstart), and install the SDK with `npm install stophy` or `pip install stophy`. Batches need an API key. This request reads four addresses as `markdown`. One is a page that does not exist, and one is not a website address.

<CodeGroup>
```bash cURL
curl -X POST https://api.stophy.dev/v1/batch/scrape \
  -H "Authorization: Bearer $STOPHY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "urls": [
      "https://example.com",
      "https://bun.com/docs/runtime/env",
      "https://bun.com/docs/this-page-does-not-exist",
      "ftp://example.com/file.txt"
    ],
    "formats": ["markdown"],
    "maxAge": 0
  }'
```
```typescript TypeScript
import { Stophy } from "stophy";

const stophy = new Stophy();

const batch = await stophy.batch.scrape({
  urls: [
    "https://example.com",
    "https://bun.com/docs/runtime/env",
    "https://bun.com/docs/this-page-does-not-exist",
    "ftp://example.com/file.txt",
  ],
  formats: ["markdown"],
  maxAge: 0,
});
console.log(batch.id, batch.invalidURLs);
```
```python Python
from stophy import Stophy

stophy = Stophy()

batch = stophy.batch.scrape(
    urls=[
        "https://example.com",
        "https://bun.com/docs/runtime/env",
        "https://bun.com/docs/this-page-does-not-exist",
        "ftp://example.com/file.txt",
    ],
    formats=["markdown"],
    max_age=0,
)
print(batch["id"], batch["invalidURLs"])
```
</CodeGroup>

`maxAge: 0` reads every page live. See [Submit a batch](/batches/submit) for every option.

## Read the response

The call answers at once, before any page is read. Starting a batch costs nothing.

Keep `id` or the returned `url` to read the batch. `invalidURLs` lists the addresses that are not public website URLs. They are skipped, and the rest of the batch runs. An address sent twice is read once.

Call `GET /v1/batch/scrape/{id}` to read the pages that have finished. This response shows only the 404 page from the batch.

```json
{
  "success": true,
  "data": [
    {
      "metadata": {
        "sourceURL": "https://bun.com/docs/this-page-does-not-exist",
        "statusCode": 404,
        "costUsd": 0,
        "error": "The page answered with status 404."
      }
    }
  ],
  "status": "completed",
  "costUsd": 0.002
}
```

Each page in `data` has the fields of a [scrape](/scrape/overview), except `scrapeId`. `total` is the pages in the batch, `completed` the pages that came back, and `failed` the pages that could not be read, which are listed in `errors`. The 404 page came back, so it counts as `completed`, with its `error` in `metadata`, and it cost nothing. `costUsd` is what the batch has cost so far. Before any page finishes, `data` is empty. `createdAt`, `completedAt` and `duration` tell you when it ran and how long it took. `expiresAt` is when the batch and its pages are deleted. See [Results](/batches/results).

## Status

Check `status` to decide when to stop polling.

| `status` | Meaning |
| - | - |
| `scraping` | The batch is waiting to start or reading pages. When it waits, `queuePosition` says where it is in line. |
| `completed` | Every page was tried. Some can still have failed: read `errors`. |
| `cancelled` | You stopped it. The pages already read are kept. |
| `failed` | The batch stopped. Your balance ran out, or no page could be read. `error` says which. |

`completed`, `cancelled` and `failed` are final. Poll the batch every few seconds, or send a `webhook` to be told as each page finishes and when the batch ends. See [Webhooks](/webhooks).

## What a batch takes

You send the list and the options once, and every page is read the way [Scrape](/scrape/overview) would read it.

| Field | What it does | Guide |
| - | - | - |
| `urls` | The pages or PDFs to read, 1 to 10,000. | [Submit](/batches/submit) |
| `formats` and the scrape options | The outputs and options every page uses: `markdown`, `html`, `links`, `screenshot`, `json`, `actions`, `location` and the rest | [Scrape](/scrape/overview) |
| `webhook` | Where to be told about each page and the end | [Submit](/batches/submit#get-told-when-pages-finish) |
| `appendToId` | Add URLs to a batch that is still running | [Submit](/batches/submit#add-urls-to-a-running-batch) |
| `maxConcurrency` | The most pages read at once | [Submit](/batches/submit#options) |
| `Idempotency-Key` header | Make a retried submit return the same batch | [Submit](/batches/submit#send-the-same-batch-twice-safely) |

## Price

Budget for each page you expect to read. A page costs what a scrape costs: $1 per 1,000 pages. A page that comes back with a 404 or 410 status, or cannot be read, costs nothing. `json` with a schema or a prompt, `summary`, `highlights`, `question`, `product`, `menu` and `changeTracking` in `json` mode add $3 per 1,000 pages each when they return something. Each page is charged when it finishes, and starting the batch is free. A batch that reads 10,000 pages costs $10. See [Pricing](/account/pricing).

## Choose another API

Pick an API based on whether you have one URL, a list, or just a site.

- [Scrape](/scrape/overview) reads one page and answers in the same call.
- [Crawl](/crawl/overview) finds the pages of a site for you and reads them in the background.
- [Map](/map/overview) lists the pages of a site, to put in a batch.
- [Monitors](/monitors/overview) read a page on a schedule and tell you when it changes.
- [Browser sessions](/browser/overview) give you a browser to drive yourself.
